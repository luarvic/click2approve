# 保持と削除 {#retention-and-deletion}

各ワークスペースでリクエスト、受信、通知を保持する期間を選択します。削除制御はリソースと権限によって異なります。

## 保持期間 を設定する {#set-retention}

1. ワークスペースを選択し、**Retention** を開きます。
2. 無料および試用プランの **Requests**、**Receipts**、および **Notifications**の期間、または有料プランの**Requests and receipts**および**Notifications**の期間を確認してください。中間のスライダー値は、スライダーのつまみの上の小さなバブル内に表示されます。エンドポイントは**1 month**と**Never delete** です。
3. プランと権限で変更が許可されている場合は、それぞれの期間を選択し、**Save** を選択します。

Personalのユーザーは自分の設定を、組織の所有者と管理者は組織の設定を管理します。Personal FreeとBusiness Trialでは、リクエストと通知の保存期間は1か月です。完了記録は作成日からPersonal Freeでは5年間、Business Trialでは1か月間保存されます。有料プランでは、**Never delete**を含めて**Requests and receipts**と**Notifications**の期間を設定できます。

Personal の無料トライアルまたはビジネス トライアルが有効になると、以前の **Never delete** 設定を含め、両方の期間が自動的に 1 か月に変更されます。スケジュールされたダウングレードでは、有料期間が終了するまで現在の保持設定が維持されます。 1 か月以上前のリクエストと通知はバックグラウンド クリーンアップの対象になります。入金のクリーンアップは、既存の入金を含め、現在の計画の入金期間に従います。クリーンアップ前にアップグレードすると、保持期間を延長できます。

!!! warning "保持はバックアップではありません"
    レコードは、保持期間後にバックグラウンド クリーンアップによって削除できます。重要なワークフロー履歴を蓄積する前に、記録保持のニーズをサポートするポリシーを選択してください。

## 保持リマインダー {#retention-reminders}

リクエストと完了記録が保持期限に達する前に、所有者は
**Retention deletion reminders** を受け取ります。標準的な通知期間は 1 週間です。各
リマインダーでは、影響を受けるレコードとその削除日が特定されます。電子メールは、そのレコード、ワークスペースの保存設定、およびこのガイドへのリンクです。
リクエストのリマインダーはリクエスト者に送信されます。完了記録のリマインダーは、完了記録の所有者にのみ送信されます。
各リクエストまたは受信ごとに 1 つのリマインダーが生成されます。保存期限を変更しても、
そのリマインダーはリセットされません。

**In-app**と**Email**の配信を**User profile → Notifications → Retention deletion reminders** で管理します。
両方とも有効になります。リマインダーを無効にしても、保存期間のクリーンアップは無効になりません。
記録をより長く保存するには、プランと権限で許可されている場合は保存期間を変更するか、
組織の所有者または管理者に連絡してください。
メール リマインダーでは [通知メール トークン](usage.md) が使用され、ワークスペースに十分な
トークンが必要です。

リマインダーは、通知設定と通常の配信の再試行に従います。
リマインダーが無効になっている場合や配信できない場合でも、保持期間のクリーンアップは設定されたスケジュールに従います。
リマインダーは自動リクエストと完了記録の保持に適用されます。
通知のクリーンアップ、手動削除、組織の削除、および支払い関連の
クリーンアップは独自のルールに従います。

## 個々のレコードを削除します {#delete-individual-records}

リクエスト、タスク、完了記録、従業員、チームに対して提供される削除アクションを使用します。テンプレート、またはそのレコードを削除する場合のみ委任します。確認メッセージと検証メッセージを読みます。

完了記録を手動で削除できるのは、完了記録の所有者だけです。手動削除と保持クリーンアップは両方とも、完了記録とその検証リンクを一緒に削除します。自分の完了記録を削除しても、元のリクエストや他の参加者の完了記録は削除されません。元のリクエストを削除しても、その完了記録は削除されません。

別のレコードからの関係により、削除が妨げられる場合があります。必要に応じて、特定された関係を解決します。再試行を繰り返しても依存関係は削除されません。

新しいリビジョンを持つリクエストは、そのリビジョンが参照している間は削除できません。リビジョン チェーンを削除する場合は、最新のリビジョンから開始してください。削除スケジュールのクリーンアップ。そのリビジョンが削除されるまで待ってから、前のリビジョンを再試行してください。

リクエストを削除すると、リクエストの経過時間に関係なく、すぐにバックグラウンド クリーンアップの対象になります。以前に消費したトークンは返金されません。

完了記録では、添付ファイルの保存期間を延長することなく、ファイルのメタデータとハッシュが保存されます。完了記録を削除しても、元の添付ファイルは削除されず、クリーンアップのスケジュールも設定されません。

削除されたワークフロー レコードに関連付けられたファイルは、後のクリーンアップをスケジュールできるため、保存されているコンテンツや使用状況はすぐには消えない場合があります。プロフィール アバターと組織ロゴは、置換または削除されるとすぐに削除できます。

## 組織を削除する {#delete-an-organization}

!!! warning "組織を削除すると、アクセス権がすぐに削除されます"
    組織の削除をスケジュールできるのは、所有者のみです。組織はすぐにワークスペースの選択から消え、アクセスできなくなります。バックグラウンド処理により、データは後で削除されます。確認する前に必要な記録を保存してください。クリーンアップの遅延は回復オプションではありません。

## 支払い関連の削除 {#payment-related-removal}

支払いの一時停止には独自の期限があります。期限までに[プラン](plans-and-billing.md)を通じて失敗した支払いを解決してください。期限切れによりビジネス組織が削除されます。 Personal ワークスペースはワークフロー データを失い、ID とプロファイルを保持したまま Personal Free に戻ります。保持設定は、この請求回復プロセスを上書きしません。
