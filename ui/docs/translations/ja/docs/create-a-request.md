# 文書承認リクエストを作成する {#create-a-request}

承認のためにドキュメントを送信するには、**リクエスト** を作成します。これには、確認するファイル、指示、各参加者に何をすべきかを指示する手順が含まれています。承認、レビュー、または電子署名を求めることができます。

最初に適切なワークスペースを選択してください。自分の名前で作品を送信するには、自分のリクエスト用のワークスペースである **Personal**を使用してください。代理で作品を送信する組織を選択します。ワークスペースによって、リクエストの所有者と使用できる担当者のタイプが決まります。**担当者** は、ステップの実行を依頼される個人またはチームです。

## リクエスト を作成します {#compose-the-request}

1. [アプリを開き](/app/)、ワークスペースを選択し、メイン メニューの **Work**グループの一番上にある**New request** を選択します。
2. 組織では、**Custom**または**From template** を選択します。テンプレートの場合は、それを選択してリクエスト エディターに進みます。
3. 「更新されたサプライヤー契約を承認する」など、特定の **Title** を入力します。
4. 目的、コンテキスト、期待される結果を説明する **Description** を追加します。
5. [参加者が確認する必要があるファイル](files.md) を添付してください。
6. [ワークフロー ステップ](workflow-steps.md) を追加して構成します。

**Request details**カードは、タイトル、**Files to review**、および説明をグループ化します。その下にワークフロー ステップを設定します。

Personal リクエストでは電子メールの担当者を使用します。

!!! info "組織の担当者"
    組織では、その組織の従業員やチームにステップを割り当てることもできます。

## 例: 承認と署名のために提案を送信する {#example-send-a-proposal-for-approval-and-signature}

1. **Files to review** の下にプロポーザルを追加します。
2. **Action**を**Approve** に設定してステップを追加し、レビュー担当者のメール アドレスを追加します。
3. **Add step**を選択し、**Action**を**Sign**に設定します。クライアントのメール アドレスを追加し、**Require an electronic signature** を有効にします。
4. 各ステップに **Instructions** と記入し、双方が何を確認すべきかを理解できるようにします。

承認ステップが成功すると、クライアントはタスクを受け取ります。複数の人が最初に承認する必要がある場合は、その人を承認ステップに追加し、**All assignees must complete** を有効にします。完了ルールについては、[ワークフロー ステップの構成](workflow-steps.md) を参照してください。

## を確認して送信します {#review-and-submit}

ファイル、ステップの順序、アクション、指示、参加者、完了ルール、可視性、および追加の要件を確認してください。直筆サインが必要な場合は、**Require an electronic signature**にチェックを入れてください。**Sign**アクションを選択しただけでは有効になりません。次に、**Submit** を選択し、ページを離れる前に確認を待ちます。

フィールドが強調表示されている場合は、修正して再送信してください。プランの制限によって送信がブロックされている場合は、[使用法](usage.md) を調べるか、組織の所有者または管理者に助けを求めてください。

組織の従業員名が不完全な場合は、レコードにどのように表示されるかを説明する警告が表示されます。 **Go back**を選択して修正するか、**Proceed anyway** を選択して現在の名前で送信します。組織の従業員の詳細は、個人プロフィールとは別に管理されます。

カスタムの新しい組織リクエストを作成するとき、**Save template** はタイトル、説明、手順からプライベート テンプレートを作成します。これはテンプレート検証ルールを適用するものであり、リクエストの送信に代わるものではありません。テンプレートから開始されたリクエストとリクエストのリビジョンでは、このアクションは提供されません。 [ワークフロー テンプレート](templates.md) を参照してください。

## 送信後、 {#after-submission}

**Requests** を開き、リクエストを選択して進行状況を追跡します。参加者は、ワークフローが各ステップに到達するにつれて行動します。通知の配信は各受信者の設定に従います。

結果、キャンセル、改訂を理解するには、[リクエストの追跡と改訂](track-requests.md) を使用してください。作成画面を離れるかキャンセルすると、確認を求めずに編集内容が破棄されます。リクエストの下書きは保存されません。
