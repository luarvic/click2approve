# ドキュメント承認の開始 {#getting-started}

レビュー、承認、または電子署名のためにドキュメントを送信するには、Click2Approve を使用します。 **リクエスト**は、ファイル、指示、参加者を含む送信する作業です。**タスク**は、そのリクエストにおける 1 人の参加者のアクションです。ワークフロー ステップは、選択した順序で実行されます。

たとえば、クライアントの電子メール アドレスに提案書を送信し、電子署名を求めます。クライアントはサインインして提案を確認し、署名を送信します。これでリクエストが完了すると、Click2Approve は **完了記録** を作成します。これは、検証リンクを通じて共有できる結果の記録です。 [完了記録と確認](receipts.md) を参照してください。

## クイック ツアー をご覧ください {#take-a-quick-tour}

サインイン後に初めてアプリを開くと、短いユーザー ガイドがプロファイル設定、通知、ワークスペース ピッカー、メイン メニュー グループを強調表示します。パスキーの設定プロンプトが表示された場合は、最初に終了するか閉じてください。

**Next**と**Back**を選択してガイド内を移動し、**Finish**を選択して完了するか、**Skip** を選択してガイドを閉じます。 Esc キーで閉じることもできます。

短い画面では、Tab キーを押して **User guide instructions** に移動し、Page Down または矢印キーを使用して説明をスクロールします。ナビゲーション ボタンは表示されたままになります。

ガイドには、現在のワークスペースで使用できるナビゲーションが表示されます。ワークスペース ピッカーが使用可能な場合について説明します。 Personal では、組織には従業員、チーム、代表団用の **People** グループがあることも説明されています。

終了またはスキップは、このブラウザのアカウントに記憶されます。別のブラウザーを使用するか、保存されているサイト データを消去すると、ガイドが再び表示されます。いつでも再度アクセスするには、メイン メニューを開いて **Support**の下の**Replay user guide** を選択します。

## 最初のリクエスト を送信します {#send-your-first-request}

1. ウェブサイトで **アプリを開く** を選択して同じブラウザ タブで続行するか、[アプリを直接開く](/app/) してから [サインインまたは登録](sign-in.md) します。
2. **Personal** (独自のリクエスト用のワークスペース) を使用するか、ワークスペース ピッカーで組織を選択して、その組織に代わって作業を送信します。
3. メイン メニューで **New request** を選択します。
4. タイトルと説明を入力し、ファイルを追加し、ステップと担当者を設定します。
5. 詳細を確認し、**Submit** を選択します。
6. **Requests** を開いて結果を確認します。

[リクエストの作成](create-a-request.md) では、送信の各部分について説明します。

## 最初のタスク を完了します。 {#complete-your-first-task}

リクエストの送信先のメール アドレスでサインインします。そのアドレスに送信されるタスクについては、ワークスペース ピッカーで **Personal**を選択します。従業員またはチームの割り当ての場合は、組織を選択します。**Tasks** を開き、タスクを選択し、その手順を読み、現在のファイルを確認します。必要なコメント、署名、または添付ファイルを入力して、決定を送信します。 [タスクを完了する](complete-a-task.md) を参照してください。

## Personal とビジネス作業 {#personal-and-business-work}

誰もが Personal ワークスペースから始めます。組織は、従業員、チーム、委任、再利用可能なワークフロー テンプレートを追加します。

!!! info "組織の機能"
    従業員、チーム、委任、テンプレートを使用する組織を選択します。 Personal では、ディスカッション、完了記録、修正、アカウントのセキュリティも利用できます。あなたの役割と計画により、どのようなアクションを実行できるかが決まります。 [機能と入手可能性](features.md) を参照してください。
