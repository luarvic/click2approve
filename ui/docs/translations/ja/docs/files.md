# ドキュメント承認のファイルと添付ファイル {#files-and-attachments}

ドキュメント承認リクエスト、参加者の決定、またはチャット メッセージにファイルを添付できます。それぞれの場所には異なる目的があります。ファイルが必要な記録の一部となるように、ファイルを添付する場所を確認してください。

|あなたがしたいのは… |ここにファイルを添付してください |
| --- | --- |
|ドキュメントを送信して他の人にレビューしてもらう | **Files to review** リクエスト作成時 |
|タスクの応答を含むファイルを送信する | **Your response** タスク |
|追加情報を共有したり、質問したりする |リクエストまたはタスクの **Chat** |

各添付ファイルは最大 **50 MiB** (52,428,800 バイト) にすることができます。これは、リクエスト、決定、およびディスカッションの添付ファイルに適用されます。ワークスペースのストレージとトークンの制限も適用されます。

## リクエスト ファイル {#request-files}

[リクエストの作成 時に参加者が確認する必要があるドキュメントを追加します](create-a-request.md)。認識可能なファイル名を使用し、送信する前に選択したファイルを確認してください。

ファイル名を開いて、利用可能なプレビューまたはダウンロード アクションを使用します。プレビューのサポートは、ファイル形式とブラウザーによって異なります。プレビューでドキュメントを表示できない場合は、ドキュメントをダウンロードして、適切なアプリケーションを使用してください。

## 意思決定の添付ファイル {#decision-attachments}

要求された場合、タスクのアクション領域に応答ファイルを添付します。 **Require an attachment** とマークされたステップは、必要な応答ファイルがないと完了できません。

記録されたタスク アクションとともに決定の添付ファイルが表示されます。同じファイルをチャットにアップロードすると、タスクの添付要件を満たしません。

## ディスカッションの添付ファイル {#discussion-attachments}

リクエストを明確にする必要がある場合は、サポート資料を [チャット メッセージ](discussions.md) に添付してください。共有する前に、ディスカッションの対象者を考慮してください。

## 改訂されたファイル {#revised-files}

改訂では、リクエスト ファイルを追加、削除、または置換できます。現在のファイル リストを確認し、コンテキストとして **Show revision changes** を使用します。置換および削除されたファイルには、現在のレビュー ドキュメントが存在しないことが示されています。

## アップロードの問題 {#upload-problems}

アップロードが完了するまで待ってから送信してください。アップロードが拒否された場合は、エラーを読み、ファイルとワークスペースの[使用制限](usage.md)を確認してください。リクエストの処理中は繰り返し送信しないでください。失敗したアクションについては、[トラブルシューティング](troubleshooting.md) を参照してください。

## トークンとストレージ {#tokens-and-storage}

ファイルのアップロード、プレビュー、ダウンロードにはトークンを使います。ファイルサイズは、別枠のストレージ上限にも算入されます。タスクやディスカッションのファイルはワークフローの作成元ワークスペースに、それ以外のアップロードは選択中のワークスペースに課金されます。アップロードは成功した場合のみ課金されます。同時転送によってトークン残高がマイナスになることがあります。ダウンロードが中断された場合も、転送済みの文書データのバイト数に応じて課金されます。[使用状況とトークン](usage.md)を参照してください。
