# 承認タスクとリクエストを委任する {#delegations}

ある従業員が承認タスクとリクエストに対処するために別の従業員を必要とする場合は、**委任**を使用します。たとえば、誰かが不在の間、同僚が仕事をカバーすることができます。両方の従業員が同じ組織に属している必要があります。

!!! info "組織のみ"
    委任を表示する組織を選択してください。所有者と管理者は、それらを作成、変更、削除できます。両方の従業員がその組織に属している必要があります。

## 委任 を作成します {#create-a-delegation}

1. 組織を選択し、**Delegations** を開きます。
2. オーナーまたは管理者として、新しい委任を開始します。
3. **Employee** — 業務を代行してもらう従業員を選びます。
4. **Delegate** で、従業員の代理となる従業員を選択します。
5. 保存して関係の方向性を確認します。

両方の従業員が選択した組織に属している必要があります。メンバーは代表団を表示できます。所有者と管理者がそれらを管理します。代理人は、別の組織の所有権を譲渡したり、メンバーシップを付与したりしません。

## 代理人として作業する {#work-as-a-delegate}

ワークスペース ピッカーで、自分が代表する従業員が含まれる組織エントリを選択します。これにより、その従業員の作業キューが選択されます。自分のエントリを選択すると、引き続き自分の作品が表示されます。委任によってキューはマージされません。

ワークスペース ページを更新すると、その選択内容が復元されるのは、委任されたアクセス権がある場合のみです。サインアウトすると、選択がクリアされます。

承認されたタスクまたはリクエストを開いて、そのコンテキストを確認し、許可されたアクションを実行します。記録には実際の代理ユーザーと従業員が保存されるため、元の担当者が行ったアクションと区別できます。

委任の方向性が重要です。アレックスをサムの代理人として選択すると、アレックスがサムの代理人として行動できるようになります。 Sam が Alex の代理を務めることは自動的に許可されません。

## 委任の変更または解除 {#change-or-remove-coverage}

所有者と管理者は、カバレッジが変更されたときに委任を編集または削除できます。保存された関係を確認し、代理人に作業リストを更新するように依頼します。委任を削除しても、委任の有効期間中にすでに記録された決定は消去されません。
