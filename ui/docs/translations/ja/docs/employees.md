# 従業員とロール {#employees-and-roles}

従業員は、ユーザー アカウントを組織に接続し、割り当てと監査レコードに使用される ID を提供します。

!!! info "組織のみ"
    従業員を表示する組織を選択します。オーナーと管理者は、従業員を追加してアクセスを管理できます。

## 従業員 を追加する {#add-an-employee}

オーナーと管理者は、**Employees** を開いて新しい従業員を開始し、電子メール、名前、役職、役割、チームを入力できます。従業員を保存し、ステータスを確認します。

電子メールには、従業員のアクセスを受け取るアカウントが指定されています。保存する前に確認してください。従業員の組織名と役職は個人プロフィールと異なる場合があります。

電子メールがまだ登録されていない従業員は **Pending**を開始します。そのメールで登録するとメンバーシップが有効になります。すでに登録されているアカウントを追加すると、**Active** 従業員が作成されます。

## 役割 {#roles}

|役割 |組織の権限 |
| --- | --- |
| User (member) |承認されたワークフローに参加し、従業員、チーム、および委任ディレクトリを表示し、独自のテンプレートを管理します |
| Admin |従業員、チーム、委任、請求、維持を管理する |
| Owner |管理管理と組織の削除をスケジュールする権限 |

ロールは、他の組織にアクセスを許可しません。リクエストとタスクの可視性は、参加、チーム関係、委任にも続きます。テンプレートはデフォルトでは非公開であり、組織の他のメンバーが表示および使用できるように共有できます。他のメンバーが所有者または管理者の場合も含め、テンプレートの作成者のみがテンプレートを編集または削除できます。

従業員の役割に関係なく、完了記録のアクセス権は完了記録の所有権に従います。所有者と管理者は、自分自身に発行された完了記録のみを表示、共有、削除できます。 [完了記録と確認](receipts.md) を参照してください。

## 従業員ステータス {#employee-status}

| Status |意味 |
| --- | --- |
| Pending |メンバーシップはまだアクティブになっていません |
| Active |従業員のアクセスは有効です |
| Disabled |従業員のアクセスは無効になっています |

オーナーと管理者は、許可された従業員の詳細、チーム メンバーシップ、**Active** 設定を編集できます。アクセスを無効にすることは、個人が組織のために行動する必要がなくなった場合に役立ちます。

## 従業員を削除する {#remove-an-employee}

利用可能な削除アクションは、従業員を削除する必要がある場合にのみ使用してください。既存の参照により削除が妨げられる場合があります。検証メッセージを読み、関連する関係を最初に解決します。過去の関係を維持する必要がある場合は、アクセスを無効にすることが適切です。

メンバーシップを変更する前に、その従業員に依存する [チーム](teams.md) と [委任](delegations.md) を確認してください。
