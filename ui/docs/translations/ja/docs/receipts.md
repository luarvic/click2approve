# 承認の完了記録とファイルの検証 {#receipts-and-verification}

**完了記録** は、リクエストの終了時に Click2Approve が作成するレコードです。リクエストの詳細、結果、参加者の記録されたアクション (提供されている場合は署名を含む) が保存されます。これを使用して、誰が行動し、どのような結果が記録されたかを確認します。

確認リンクを通じて完了記録を共有できます。リンクを知っている人は、記録を確認して、ドキュメントのコピーが完了記録に記録されているファイルと一致するかどうかを確認できます。

!!! info "完了記録を管理できるのは誰ですか?"
    完了記録が発行されたユーザーのみが、ワークスペースで完了記録を開いたり削除したり、その検証リンクを管理したりできます。これは、Personal と組織の両方に当てはまります。所有者と管理者は、その役割を通じて他の人の完了記録を開くことはできません。

リクエストが完了、キャンセル、または新しい改訂版に置き換えられると、依頼者と実際にタスクを受け取った各担当者に完了記録が発行されます。複数のタスクを持つ場合や依頼者を兼ねる場合も、1人につき、ワークスペースとリクエストの改訂版ごとに1件です。タスクを完了していなくても発行され、記録された状態で割り当てと実行済みの操作を区別できます。タスクを生成しなかったステップでは、担当者向けの完了記録は発行されません。

## 完了記録 を開く {#open-a-receipt}

リクエストを送信したか、タスクを完了したワークスペースで **Receipts**を開き、そのリクエストの完了記録を選択します。**Receipt**カード ヘッダーには、短い番号、一致するリクエストおよびタスク カード ヘッダーが含まれます。カードには完全な ID と日付が表示され、その後に**Request**セクションと**Task**セクションが記録された詳細、結果、参加者、アクション、署名が存在する場合に表示されます。**Request**と**Task** セクションの見出しには、ワークスペースの完了記録と共有確認ページの両方に短い番号が含まれています。完全なリクエスト ID とタスク ID は、利用可能な場合は記録された詳細に残ります。

受信日には、秒なしでローカルの日付と時刻が使用されます。空のフィールドと最初のリビジョン番号は非表示になります。

印刷時に、リクエスト セクションとタスク セクションを複数のページにまたがって続けることができます。セクションの見出しは最初の行に残り、個々の詳細行と署名はページに収まるときに一緒に残ります。

完了記録には、完了した作業の記録されたコンテキストが保存されます。参加者固有の可視性により、完了記録に含まれるステップを制限できます。完了記録はライブ リクエストとは別のものです。

## 確認リンク を作成します {#create-a-verification-link}

1. 自分で管理できる完了記録を開きます。
2. **Share** を選択します。
3. **New link**を選択し、**Expires** を設定して、リンクを作成します。
4. リスト内で作成したリンクを選択して確認 URL を開き、それをコピーして目的の受信者と共有します。

完了記録 カード内の QR コードにより、同じ確認リンクが開きます。カードの上にある Click2Approve ロゴまたはブランド名を選択して、ホームページを開きます。

!!! warning "リンクを知っている人は誰でも完了記録を表示できます"
    アクティブな確認リンクにより、ワークスペースのメンバーシップを必要とせずに完了記録が開きます。共有する前に確認してください。その内容には、名前、決定事項、署名が含まれる場合があります。

## ファイル を確認する {#verify-a-file}

ワークスペースまたはアクティブな確認リンクで完了記録を開き、**Verify file**を選択します。ドキュメントのコピーを選択します。ブラウザは、ファイルの内容に基づいて値**SHA-256 hash** を計算します。 Click2Approve は、その値を完了記録に記録されたハッシュと比較し、ファイルがリクエスト ファイルまたは参加者の応答添付ファイルと一致するかどうかを示します。このチェックでは、ブラウザで選択したファイルを読み取ります。そのコピーはアップロードされません。

たとえば、承認された提案とその受信リンクが誰かから送られてきた場合は、リンクを開いて **Verify file** を使用して提案を確認します。内容が変更されたファイルは、ファイル名が同じであっても、記録されたハッシュと一致しません。

結果は **Verify file**の上に表示されます。**File verified**は、一致する添付ファイルとそのリクエストまたはタスクを識別します。**File does not match** は、同じハッシュを持つ記録ファイルがないことを意味します。正しいバージョンを選択していることを確認して、再試行してください。

検証では、完了記録に保存されているファイルのメタデータとハッシュが使用されます。元の添付ファイルが削除された後も機能します。完了記録を保持しても、保存されている添付ファイルは保持されません。

一致により、ファイルの内容が記録されたファイルと一致することが確認されます。文書の主張を評価したり、署名者の身元を独自に検証したりすることはありません。

## の共有を停止します {#stop-sharing}

**Share**でリンクを選択し、**Remove** を選択して、アクセスが不要になったことを確認します。期限切れまたは取り消されたリンクでは、完了記録が提供されなくなります。別のリンクを作成しても、既存のリンクの有効期限は延長されません。

検証が失敗した場合は、完了記録の所有者に現在のリンクを問い合わせてください。パブリック検証リンクは、組織のリクエスト、タスク、ディレクトリではなく、その完了記録へのアクセスを提供します。

## 完了記録保持 {#receipt-retention}

バックグラウンド クリーンアップでは、完了記録作成時から測定される完了記録ワークスペースの [保持ポリシー](retention.md) に従って、完了記録とその検証リンクが削除されます。

|計画 |完了記録の保持 |
| --- | --- |
| Personal Free | 5 年 |
| Business Trial | 1 か月 |
|有料プラン | **Never delete**を含む、構成された**Requests and receipts** 期間 |

個人の担当者の完了記録は、要求側の組織の計画とは関係なく、Personal ワークスペースのポリシーに従います。計画を変更すると、まだ削除されていない既存の完了記録のポリシーが変更されます。元のリクエストを削除しても、その完了記録は削除されません。ワークスペースの削除や支払い関連のクリーンアップでは、完了記録をより早期に削除できます。

確認リンクは、完了記録の独立したバックアップではありません。リンクを取り消すと、完了記録は削除されずに共有が停止されます。

## 完了記録 を削除します {#delete-your-receipt}

完了記録で **Delete**を選択し、**Delete receipt** で確認します。これにより、完了記録とそのすべての確認リンクが完全に削除されます。元のリクエストや他の参加者に発行された完了記録は削除されません。所有者と管理者は、自分自身に発行された完了記録のみを削除できます。

完了記録を保持したまま共有を停止するには、代わりにその確認リンクを取り消します。
