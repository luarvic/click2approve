# ドキュメントの確認、承認、または署名 {#complete-a-task}

**タスク**では、ドキュメント承認リクエストの 1 つのステップに基づいて行動することが求められます。 **Tasks** を開いて、自分に割り当てられたドキュメントを確認、承認、または署名します。決定を記録する前に、現在のドキュメントと手順をお読みください。

## タスク を見つけます。 {#find-the-task}

1. タスクの送信先のアカウントで [アプリを開きます](/app/)。
2. ワークスペース ピッカーで、電子メール アドレスに送信されたタスクとして **Personal** を選択します。 Personal は、直接送信される独自のリクエストとタスク用のワークスペースです。従業員またはチームの割り当ての場合は、代わりに組織を選択します。
3. **Tasks** を開き、アクションを待機しているタスクを選択します。
4. タイトル、依頼者、説明、手順手順、および現在のファイルを読みます。

チーム割り当ての場合、**Assigned to**には、タスクを受信している個々の従業員が従業員アイコン付きで表示されます。**Workflow**タブでステップ見出しを展開し、元の担当者と設定を確認します。タスク カードは見出しの下に表示されたままになります。チーム作成のタスクを展開すると、チームを識別する**Assigned via** が表示されます。

タスク リストとリクエスト リストは同じ列と幅を使用します: **#**、**Title**、**Revision**、**Status**、 **Requested by**および**Created**。小さい画面では、タイトルの下に二次的な詳細が表示されます。タスクを開いて、組織が記録されているときに **From organization** を確認します。

リストに戻るには、タスク タイトルの上にある **Tasks** パンくずリストを使用します。

組織からのメールアドレス指定のタスクは、Personal に届きます。その組織のワークスペースへのアクセスは許可されません。組織の代表者は、承認されたタスクを実行することもできます。 [委任](delegations.md) を参照してください。

## 必要な情報を入力します {#provide-the-required-information}

タスクの概要の下で、**Your response** を使用して決定を選択し、必要に応じて添付ファイル、コメント、署名を入力します。

タスクに提供されたアクションを使用します。ワークフローでは、コメント、応答の添付、電子署名、またはこれらの組み合わせが必要な場合があります。送信する前に、すべての必須フィールドに入力してください。否定的な決定には、結果を説明するコメントが必要です。

署名については、**Legal name**を確認し、該当する場合は**Representation details** と入力し、署名を入力してください。 [保存されたプロファイル署名](profile.md) を図面に事前入力できます。この決定のためにそれを確認してください。

## 承認、拒否、または変更のリクエスト {#approve-reject-or-request-changes}

応答の選択肢は、ステップの **Action** によって異なります。一般的な選択肢は次のとおりです。

|ステップアクション |肯定的な反応 |否定的な応答 |
| --- | --- | --- |
| Approve | **Approve**|**Reject** |
| Review | **Review**|**Request changes** |
| Sign | **Sign**|**Decline** |

否定的な応答にはコメントが必要で、失敗した結果でリクエストが停止されます。たとえば、レビュー タスクで **Request changes** を選択し、ドキュメントのどの部分を更新する必要があるかを説明します。リクエスト者は、[対象となるリクエストを修正して再送信](track-requests.md#revise-and-resubmit)できます。

アクションを記録する前に、[チャット](discussions.md) を使用してリクエストを明確にします。チャット メッセージではタスクは完了しません。チャットで送信されたファイルは **Require an attachment**を満たしていません。そのファイルを**Your response** の下に追加します。 [ファイルと添付ファイル](files.md) を参照してください。

## 決定を送信する {#submit-the-decision}

タスクで提案された場合の否定的な結果も含め、決定に一致するアクションを選択します。送信する前に、決定と確認事項を確認してください。成功のフィードバックを待ちます。

記録されたアクションはリクエスト履歴の一部になります。応答が成功した後、ステップは完了ルールに応じて、他の担当者を待つか、すぐに進むことができます。否定的な応答は、失敗した結果でワークフローを終了します。

## 後で戻る {#return-later}

タスク ページを離れると、確認を求めずに未送信の応答が破棄されます。タスクを完了して決定を記録します。

タスクを再度開いて、記録されたアクションとコンテキストを確認します。タスクは、キャンセル、スキップ、改訂によって置き換えられた場合、または別の適格な参加者によって完了された場合に、完了できなくなる可能性があります。エラー後にアクションを再試行する前にタスクを更新します。

タスク カードのヘッダーのステータス チップには、現在の状態や記録されたアクション (保留中、署名済み、拒否済みなど) が表示されます。
