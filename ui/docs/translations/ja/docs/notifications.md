# 承認メールとアプリ内通知 {#notifications}

通知は、割り当てられたタスク、リクエストの結果、ディスカッション、完了記録、請求イベントに戻るのに役立ちます。カテゴリごとに配信設定を個別に設定します。

## 通知 を確認する {#review-notifications}

アプリの通知ビューを開いてアプリ内イベントを確認します。関連するリソースへの通知に従って、行動する前に現在の状態を確認してください。古い通知は、完了、キャンセル、または置き換えられたタスクを指す場合があります。

通知と電子メールの件名には、**Step succeeded**または**Step failed**が表示され、結果がわかっている場合は**Request succeeded**または**Request failed**が表示されます。電子メールの件名にはリクエストのタイトルが追加されます。キャンセルされたリクエストと置き換えられたリクエストには、個別の電子メール件名が付けられます。他のイベントでは、**New task**、**Task completed**(自動完了用)、**New message**、**New receipt** を使用します。

電子メール リンクは、関連するタスク、リクエスト、完了記録、または計画ページを対象としています。プロンプトが表示されたら、目的のアカウントでサインインします。

アカウント、ワークフロー、請求メールは、アプリのフッターとホーム、アプリ、ドキュメント、連絡先、利用規約、およびプライバシーのリンクを共有します。セキュリティに関する通知と配信の説明がフッターの上に表示されます。

## 配信設定を設定します {#set-delivery-preferences}

1. **User profile → Notifications** を開きます。
2. カテゴリを確認します: **Request notifications**、**Task notifications**、**Chat notifications**、**Receipt notifications**、**Retention deletion reminders**、**Billing recovery reminders**。
3. サポートされているカテゴリごとに **In-app**スイッチと**Email** スイッチを設定します。
4. **Save** を選択します。

設定が保存されていないカテゴリは有効になります。スイッチを変更し、**Save**を選択して設定を保存します。**Billing recovery reminders**のアプリ内オプションは無効になっています。その電子メール設定は、他のカテゴリとは別に管理されます。設定によってアクセス権が拡張されたり、ディスカッションの対象者に追加されたりすることはありません。**Retention deletion reminders** は、
自動の保持クリーンアップの前にリクエストと完了記録の所有者に警告します。彼らのメールは、保存設定と
[保存と削除のガイド](retention.md) にリンクしています。このカテゴリを無効にしても、
保持の削除は無効になりません。

## メッセージが欠落しています {#missing-messages}

メール アドレス、スパム フォルダ、通知設定、選択したワークスペース、受信資格があるかどうかを確認してください。メールの配信には時間がかかる場合があります。

今すぐ行動する必要がある場合は、メールを待つのではなく、タスクまたはリクエストを直接開きます。配信失敗の場合は、認証情報を共有せずに、イベント時間とリソース コンテキストに関するサポートを提供します。

## 電子メール トークン {#email-tokens}

保持リマインダーを含むワークフロー電子メールは、受信者ごとにトークンを消費し、元のワークスペースに請求されます。トークンは送信前にチェックされ、電子メール プロバイダーが送信を受け入れるときに課金されます。通知をキューに入れるとトークンは消費されません。無効化された電子メール配信には料金はかかりません。セキュリティ、アカウント回復、請求メールは、ワークスペース トークンの料金なしで含まれています。 [使用法とトークン](usage.md) を参照してください。
