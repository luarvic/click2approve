# チームにドキュメント承認ステップを割り当てる {#teams}

チームは 1 つの組織内の従業員をグループ化し、ドキュメント承認ステップをグループに割り当てることができます。たとえば、提案をレビューする人々のチームを作成し、レビュー手順を設定するときにそのチームを選択します。ステップの完了ルールは、割り当てられたすべてのユーザーが正常に応答する必要があるか、または 1 人のユーザーが正常に応答する必要があるかを制御します。

!!! info "組織のみ"
    チームを表示する組織を選択します。オーナーと管理者はチーム メンバーシップを管理します。

## チーム を作成または更新します。 {#create-or-update-a-team}

1. 組織を選択し、**Teams** を開きます。
2. オーナーまたは管理者として、新しいチームを開始するか、編集するチームを開いてください。
3. 認識可能な **Name** を入力します。
4. チームに所属する組織の **Employees** を選択します。
5. メンバーシップを保存して確認します。

メンバーはチーム ディレクトリを表示できます。所有者と管理者が管理します。別の組織のユーザーをこのチームの従業員として追加することはできません。

## チーム に作業を割り当てる {#assign-work-to-a-team}

[ワークフロー ステップ](workflow-steps.md) を構成する場合、担当者のタイプとして **Team** を選択し、チームを選択します。ステップのすべての担当者ルールまたは任意の担当者ルールを確認して、意図した完了要件と一致するようにしてください。

メンバーシップの変更は、今後のタスク割り当てに適用されます。参加者にすでに割り当てられているタスクは、参加者がチームを離れた後もその参加者のものになります。

チームの関係は、ユーザーがどの組織のタスクとリクエストを利用できるかに影響します。予期した作業が見つからない場合は、現在のワークスペースと従業員のチーム メンバーシップの両方を確認してください。

## チームを削除 {#remove-a-team}

チームが不要になった場合は、利用可能な削除アクションを使用します。他のレコードからの参照により、削除が妨げられる場合があります。割り当てを変更したり、アクティブなワークフローやテンプレートで使用されているチームを削除したりする前に、報告された関係を確認してください。
