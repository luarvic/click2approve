# ドキュメント承認ワークフローのステップを構成する {#configure-workflow-steps}

承認ワークフローは、誰がどの順序でドキュメントを処理するかを定義します。 **担当者**は、ステップに割り当てられた個人またはチームです。ステップが次々と実行されます。複数の担当者が同じステップで操作できます。**Add step** を使用して別のステップを作成し、矢印コントロールで順序を変更し、削除ボタンを使用して削除します。

## 順次承認および並行承認 {#sequential-and-parallel-approvals}

ある決定を別の決定よりも先に行う必要がある場合は、別のステップを使用します。これは**順次承認**です。たとえば、レビュー担当者がステップ 1 で提案を承認し、クライアントがステップ 2 で署名します。

同時にレビューできる場合は、同じステップに参加者を配置します。これは、そのステップ内の**並行承認**です。ステップ自体は引き続き順番に実行されます。

|必要なのは… |このようにワークフローを構成します |
| --- | --- |
| 1人の確認後にもう1人が確認 | 確認者ごとに別のステップを追加 |
|両方の承認が必要な 2 人の査読者 |両方を 1 つのステップに追加し、**All assignees must complete** を有効にします |
|複数の人物のいずれかの承認 |これらを 1 つのステップに追加し、**All assignees must complete** は無効のままにしておきます |
|承認後の署名 | **Approve**ステップを追加し、**Require an electronic signature**を有効にして**Sign** ステップを追加します |

## アクションと参加者を選択します {#choose-an-action-and-participants}

各ステップで **Action** を選び、分かりやすい **Instructions** を入力します。選択できる操作は Approve、Sign、Confirm、Acknowledge、Review、Verify、Accept、Complete です。記録したい判断に合った操作を選んでください。

電子メールで担当者を追加し、送信する前に表示される名前とアドレスを確認してください。

!!! info "組織担当者"
    組織で、**Employee**または**Team** を選択して、現在の組織内で作業を割り当てます。これらの担当者タイプは、Personal では使用できません。

## すべての担当者または任意の担当者 を要求します {#require-everyone-or-any-assignee}

**All assignees must complete**を有効にして、すべての担当者からの正常な応答を要求します。このオプションを無効にすると、1 つの成功した応答によってステップが完了し、他の保留中のタスクがスキップされます。このスイッチは、ステップに複数の担当者またはチーム割り当てがある場合に表示されます。**All assignees must complete** が無効な場合でも、否定的な決定によりリクエストは失敗の結果で停止されます。このオプションでは、他の担当者が拒否を無効にすることはできません。

たとえば、両方とも行動する必要がある 2 人のレビュー担当者に対して 1 つのステップを使用し、その後に別の署名ステップを使用します。参加可能な 1 人の参加者が必要な決定を提供できる場合は、任意の担当者オプションを使用します。

## 追加要件 {#additional-requirements}

**Additional requirements**セクションと**Visibility** セクションは、リクエストの作成または改訂中、またはテンプレートの編集中に各ステップで表示されたままになります。保存または送信する前に設定を確認してください。

参加者が満たさなければならない要件を有効にします。

- **Require a comment** 説明を収集します。
- **Require an electronic signature** 署名の詳細と署名を収集します。
- **Require an attachment** は応答ファイルを収集します。

アクション ラベルと電子署名の要件は別個の設定です。描画署名が必要な場合は、署名要件を有効にします。参加者が何を提供すべきかを理解できるように、選択したアクションとともに要件を確認します。 [タスクを完了する](complete-a-task.md) を参照してください。

## ステップの可視性 {#step-visibility}

要求者とステップの直接の担当者は、メール担当者を含め、常にそのステップを表示できます。 **Visibility** は、その詳細と応答の添付ファイルを誰が閲覧できるかを制御します:

|設定 |追加の対象者 |
| --- | --- |
| All participants |リクエストにアクセスできる参加者 |
| Assignees and organization participants |組織の参加者。組織のワークフローで利用可能 |
| Assignees only |追加の参加者なし |

電子メールの割り当ては、電子メールが組織の従業員に属している場合でも、受信者の Personal ワークスペースに残ります。割り当てられたステップはワークフローに表示されたままになり、ステップ チャットに使用でき、受信者の完了記録に含まれます。

これらの設定では、ワークスペースのメンバーシップや無関係なリクエストへのアクセスが許可されません。他の参加者がステップの詳細を必要としない場合は、制限付き設定を選択してください。

## リビジョン {#revisions}

[リクエストを再送信する](track-requests.md)場合は、新しいリビジョンの手順を確認して編集します。そのワークフローは最初のステップから再び始まります。以前の決定は、以前の改訂版とその完了記録に記録されたままになります。頻繁に使用する組織ワークフローの場合、ステップを [テンプレート](templates.md) として保存します。
