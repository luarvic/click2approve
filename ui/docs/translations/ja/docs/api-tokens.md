# 承認ワークフロー統合用の API トークン {#api-tokens}

Click2Approve API を使用して、独自のツールを接続し、承認ワークフローを自動化します。 API トークンを使用すると、統合はユーザー アカウントを通じて API にアクセスできます。 Personal で働いているか組織で働いているかに関係なく、プロファイルでそれらを管理します。

## トークン を作成する {#create-a-token}

1. **User profile → API tokens** を開きます。
2. **New API token** を選択します。
3. 必要に応じて、認識可能な名前と有効期限を入力します。
4. トークンを作成し、ダイアログを閉じる前にその値をコピーします。
5. 目的の統合のために安全に保管してください。

!!! warning "閉じる前にトークンをコピーします"
    完全な値は 1 回だけ表示されます。安全に保管し、メッセージ、スクリーンショット、ソース管理から遠ざけてください。紛失した場合は、代替トークンを作成し、古いトークンを取り消します。

## API を確認する {#explore-the-api}

[API リファレンス (Swagger UI)]({{ api_reference_url }}) を開きます{target="_blank" rel="noopener noreferrer"} を使用して、エンドポイント、リクエスト フィールド、レスポンスを参照します。

認証されたリクエストを試行するには、**Authorize**を選択し、`Bearer` プレフィックスを付けずに API トークンを貼り付け、確認します。 Swagger は認証ヘッダーを追加します。エンドポイントを選択し、**Try it out**を選択し、必須フィールドに入力して、**Execute** を選択します。これらのリクエストはアカウントを使用し、実際のデータを作成、変更、削除する可能性があります。

アカウント セキュリティ エンドポイントには対話型のサインイン セッションが必要であり、API トークンでは使用できません。

## 統合でトークンを使用する {#use-a-token-in-your-integration}

トークンを各 API リクエストの `Authorization` ヘッダー:

```http
Authorization: Bearer YOUR_API_TOKEN
```

`YOUR_API_TOKEN` を、トークンの作成時にコピーした値に置き換えます。トークンはアカウントの権限に従って機能します。トークンを作成しても、別のユーザーの仕事や別の組織のリソースへのアクセスは許可されません。認証は引き続き適用されます。

## トークン を取り消す {#revoke-a-token}

リストでトークンを選択し、**Revoke** を選択して確認します。代替認証情報を使用してそれを使用した統合を更新します。漏洩の疑いがある未使用のトークンと認証情報を取り消します。

API トークンはアカウント設定です。ワークスペースを切り替えても、別のトークンのセットは作成されません。
