# 文書承認機能とワークスペース アクセス {#features-and-availability}

Click2Approve は、文書レビュー、承認手順、電子署名、リクエスト追跡を組み合わせたものです。個別の作業には、**Personal** (独自のリクエストや電子メールでアドレス指定されたタスク用のワークスペース) を使用します。共有ビジネス ワークフローには組織ワークスペースを使用します。ワークスペース、ロール、およびプランによって、実行できるアクションが決まります。

Click2Approve API を介して独自のツールに接続することもできます。認証情報を作成し、統合リクエストを認証するには、[API トークン](api-tokens.md) を参照してください。

!!! info "組織のみ"
    従業員、チーム、代表団、ワークフロー テンプレートは組織に属します。ワークスペース ピッカーで組織を選択して使用します。このガイドの他の機能は、Personal でも利用できます。

## 文書承認の仕組み {#how-document-approval-works}

1. ドキュメントと手順を含む [リクエストを作成](create-a-request.md)。
2. [ワークフロー ステップの構成](workflow-steps.md) を使用して、誰がどの順序で行動するかを選択します。複数の人が同じ手順でレビューできます。
3. 参加者は **Tasks** を開いて [決定を記録](complete-a-task.md) します。ステップでは、コメント、電子署名、または応答ファイルが必要になる場合があります。
4. **Requests** を開いて [進行状況を確認](track-requests.md)します。リクエストが完了すると、[完了記録](receipts.md) はその結果と記録されたアクションを保存します。

例えば、最初のステップで2人が提案書を確認し、後のステップで顧客が署名できます。手書き署名が必要な場合は、そのステップで **Require an electronic signature** を有効にしてください。

## 組織の権限 {#organization-permissions}

メンバーは、従業員、チーム、および委任のディレクトリを表示できます。所有者と管理者は、従業員、チーム、委任、請求、保持を管理します。テンプレートはデフォルトではプライベートです。作成者は、他の組織メンバーが表示および使用できるようにそれらを共有できます。テンプレートを編集または削除できるのは作成者だけです。完了記録へのアクセスは、各完了記録が発行されるユーザーに制限されます。組織の削除をスケジュールできるのはオーナーだけです。

リクエストまたはタスクへのアクセスは、参加、チーム関係、および委任によって異なります。組織のメンバーシップだけでは、すべてのワークフローが公開されたり、別の組織のレコードへのアクセスが許可されたりするわけではありません。

ロールの参照については [従業員とロール](employees.md) を、プランの制限については [使用法と制限](usage.md) を参照してください。 **Plans** を開いて、現在の手当と利用可能なプランの選択肢を確認してください。
