# 承認ステータスを追跡し、リクエストを修正する {#track-and-revise-requests}

ドキュメントの承認ステータスを確認するには、リクエストを所有するワークスペースで **Requests**を開きます。個人的に送信した作業には、自分のリクエスト用のワークスペース**Personal** を使用してください。組織に代わって送信された作業の場合は、その組織を選択します。

利用可能なフィルタを使用してリクエストを見つけ、その詳細を開いてファイル、ステップ、参加者、記録されたアクションを確認します。自分に割り当てられたアクションについては、代わりに **Tasks** を開きます。 [タスクを完了する](complete-a-task.md) を参照してください。

## 進行状況と結果の読み取り {#read-progress-and-outcomes}

ワークフロー ステップはリクエストの概要の下に表示されます。各ステップの見出しには、**Step 1 · Approve** のように、その番号とアクションが表示されます。見出しを展開すると、完了ルール、表示設定、要件、元の担当者が表示されます。担当者アイコンは、チーム、従業員、電子メール アドレスを識別します。ステップの詳細を折りたたんでも、タスク カードは表示されたままになります。

タスクがチームの割り当てからのものである場合は、タスクを展開すると **Assigned via**が表示されます。**Upcoming task**は、タスクがまだ開始されていないユーザーを示します。**From organization** がタスクに表示されると、記録された組織の名前が示されます。 Personal は組織ではなくワークスペースです。

各リクエストまたはタスク カードのヘッダーのステータス チップには、カードが折りたたまれているときを含む現在の状態が表示されます。

|状態 |意味 |
| --- | --- |
| Pending |提出された作業は進行を待っています |
| Started |ワークフローは進行中です |
| Completed — Succeeded |ワークフローは正常に完了しました |
| Completed — Failed |ワークフローは失敗しましたが完了しました |
| Canceled |リクエストは停止されました |
| Superseded |このリクエストは新しいリビジョンに置き換えられました |

個々のタスク アクションには、署名済み、拒否済みなど、より具体的なラベルを付けることができます。タスクがスキップされたからといって、参加者が決定を下したわけではありません。別の結果によってすでにステップが解決されている可能性があります。自動的に完了したリクエストとスキップまたはキャンセルされたタスクには、**Completed by** フィールドなしでステータスと完了時間が表示されます。

## リクエストをキャンセルする {#cancel-a-request}

管理権限のある保留中または開始済みのリクエストを開き、**Cancel request** を選択して確認します。キャンセルするとワークフローが停止します。参加者に連絡する前に、リクエストを再度開いて最終状態を確認します。

## を修正して再送信します。 {#revise-and-resubmit}

Personal または組織で対象となるリクエストを修正します。

たとえば、レビュー担当者は **Request changes**を選択し、提案書の価格が誤っていることを説明する場合があります。**Resubmit** を使用して提案を置き換え、新しいレビューを開始します。 [チャット](discussions.md) にファイルを追加しても、リクエストの現在のレビュー ファイルは置き換えられません。

1. 対象となるリクエストを開き、**Resubmit** を選択します。
2. 前のリビジョンのファイル、手順、ワークフローの手順を確認します。
3. 新しいリビジョンのファイル、手順、手順を更新します。
4. 参加者を確認し、**Submit** を選択します。

再送信すると新しいリビジョンが作成され、前のリクエストが置き換えられます。このアクションは、成功せず、新しいリビジョンがない、適格な保留中、開始済み、または完了したリクエストに対してのみ提供されます。正常に完了したリクエストをこのアクションで再送信することはできません。

新しいリビジョンはワークフローを最初のステップから開始します。以前の決定は、以前の改訂版とその完了記録に記録されたままです。新しいリビジョンではタスクは完了しません。再送信する前に、すべてのステップと参加者を確認してください。

**Show revision changes** が存在する場合、これを使用して、追加、置換、削除されたファイルを検査します。置換または削除されたファイルはリビジョンのコンテキストのままであり、確認する現在のファイルの一部ではありません。

## 結果 を保存する {#preserve-the-result}

[完了記録](receipts.md) は、ステップの可視性に従って、リクエストの結果と各参加者の記録されたアクションを記録します。これらは、リクエストが完了するか、キャンセルされるか、新しいリビジョンに置き換えられるときに作成されます。リクエストを削除したり、長期アクセスに依存したりする前に、[保持と削除](retention.md) を確認してください。

新しいリビジョンでは、参照するリクエストの削除が防止されます。最初に最新リビジョンの削除をスケジュールし、バックグラウンドでのクリーンアップを待ってから、以前のリビジョンを削除します。リクエストを削除しても、参加者の完了記録は削除されません。
