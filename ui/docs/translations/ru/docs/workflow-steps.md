# Настройте шаги рабочего процесса утверждения документа {#configure-workflow-steps}

Рабочий процесс утверждения определяет, кто и в каком порядке действует над документом. **Исполнитель** — это человек или команда, назначенные на этап. Шаги идут один за другим. На одном этапе могут действовать несколько ответственных лиц.

Используйте **Add step** для добавления этапа, стрелки — для изменения порядка и кнопку удаления — для удаления этапа.

## Последовательное и параллельное утверждение {#sequential-and-parallel-approvals}

Используйте отдельные шаги, когда одно решение должно предшествовать другому. Это **последовательное одобрение**. Например, рецензент одобряет предложение на шаге 1, затем клиент подписывает его на шаге 2.

Поместите людей на один и тот же этап, когда они смогут просматривать предложение одновременно. Это **параллельное утверждение** на этом этапе. Сами шаги по-прежнему выполняются по порядку.

| Вам нужно… | Настройте рабочий процесс таким образом |
| --- | --- |
| Один рецензент, за ним другой | Добавьте отдельный шаг для каждого рецензента |
| Два рецензента, которые оба должны одобрить | Добавьте оба действия в один шаг и включите **All assignees must complete** |
| Одобрение от любого из нескольких человек | Добавьте их в один шаг и оставьте **All assignees must complete** отключенным |
| Одобрение с последующей подписью | Добавьте шаг **Approve**, затем шаг **Sign** с включенным **Require an electronic signature** |

## Выберите действие и участников {#choose-an-action-and-participants}

Для каждого этапа выберите **Action** и заполните понятные **Instructions**. Доступны действия Approve, Sign, Confirm, Acknowledge, Review, Verify, Accept и Complete. Выберите действие, соответствующее решению, которое нужно зафиксировать.

Добавьте ответственных по электронной почте и проверьте отображаемые имена и адреса перед отправкой.

!!! info "Назначенные организации"
    В организации выберите **Employee** или **Team**, чтобы поручить работу внутри текущей организации. Эти типы исполнителей недоступны в Personal.

## Требовать от всех или любого исполнителя {#require-everyone-or-any-assignee}

Включите **All assignees must complete**, чтобы требовать успешный ответ от каждого исполнителя. Если этот параметр отключен, один успешный ответ завершает шаг и пропускает другие ожидающие задачи. Переключатель появляется, когда у шага несколько исполнителей или назначена группа.

Отрицательное решение останавливает запрос с неудачным результатом, даже если **All assignees must complete** отключен. Эта опция не позволяет другим ответственным лицам отменять отказ.

Например, используйте один шаг для двух рецензентов, которые оба должны действовать, а затем отдельный шаг подписания. Используйте опцию «любой исполнитель», если один доступный участник может принять необходимое решение.

## Дополнительные требования {#additional-requirements}

Разделы **Additional requirements** и **Visibility** остаются видимыми на каждом этапе при создании или пересмотре запроса или редактировании шаблона. Просмотрите их настройки перед сохранением или отправкой.

Включите требования, которым должен соответствовать участник:

- **Require a comment** для сбора объяснений.
- **Require an electronic signature** для сбора данных для подписи и нарисованной подписи.
- **Require an attachment** для сбора файла ответов.

Метка действия и требования к электронной подписи – это отдельные настройки. Включите требование подписи, если требуется нарисованная подпись. Просмотрите требования вместе с выбранным действием, чтобы участники знали, что им предоставить. См. раздел [Выполнение задачи](complete-a-task.md).

## Видимость шага {#step-visibility}

Отправитель запроса и прямые исполнители шага всегда могут видеть этот шаг, включая ответственных по электронной почте. **Visibility** определяет, кто еще может видеть его подробную информацию и вложения ответов:

| Настройка | Дополнительная аудитория |
| --- | --- |
| All participants | Участники, имеющие доступ к запросу |
| Assignees and organization participants | Участники организации; доступно для рабочих процессов организации |
| Assignees only | Никаких дополнительных участников |

Назначения электронной почты остаются в рабочей области Personal получателя, даже если их электронная почта принадлежит сотруднику организации. Назначенные шаги остаются видимыми в рабочем процессе, доступны для пошагового чата и включаются в запись о результате получателя.

Эти настройки не предоставляют членство в рабочей области или доступ к несвязанным запросам. Выберите ограниченную настройку, если другим участникам не нужны подробности этого шага.

## Новые версии {#revisions}

При [повторной отправке запроса](track-requests.md) просмотрите и отредактируйте шаги для новой версии. Его рабочий процесс начинается снова с первого шага; предыдущие решения остаются записанными в предыдущей редакции и ее записях о результате. Для часто используемых рабочих процессов организации сохраните шаги как [шаблон](templates.md).
