# Überprüfen, genehmigen oder signieren Sie ein Dokument {#complete-a-task}

Eine **Aufgabe** fordert Sie auf, auf einen Schritt einer Dokumentgenehmigungsanfrage zu reagieren. Öffnen Sie **Tasks**, um ein Ihnen zugewiesenes Dokument zu überprüfen, zu genehmigen oder zu unterzeichnen. Lesen Sie die aktuellen Dokumente und Anweisungen, bevor Sie Ihre Entscheidung festhalten.

## Finden Sie die Aufgabe {#find-the-task}

1. [Öffnen Sie die App](/app/) mit dem Konto, an das die Aufgabe gesendet wurde.
2. Wählen Sie in der Arbeitsbereichsauswahl **Personal** für Aufgaben aus, die an Ihre E-Mail-Adresse gesendet werden. Personal ist der Arbeitsbereich für Ihre eigenen Anfragen und Aufgaben, die direkt an Sie gesendet werden. Wählen Sie für Mitarbeiter- oder Teamzuweisungen stattdessen die Organisation aus.
3. Öffnen Sie **Tasks** und wählen Sie die Aufgabe aus, die auf Ihre Aktion wartet.
4. Lesen Sie den Titel, den Anforderer, die Beschreibung, die Schrittanweisungen und die aktuellen Dateien.

Bei einer Teamaufgabe zeigt **Assigned to** den einzelnen Mitarbeiter, der die Aufgabe erhält, mit einem Mitarbeitersymbol an. Erweitern Sie auf der Registerkarte **Workflow** die Überschrift eines Schritts, um die ursprünglichen Beauftragten und Einstellungen zu überprüfen. Aufgabenkarten bleiben unterhalb der Überschrift sichtbar. Erweitern Sie eine vom Team erstellte Aufgabe, um **Assigned via** anzuzeigen, das das Team identifiziert.

Die Aufgaben- und Anforderungslisten verwenden dieselben Spalten und Breiten: **#**, **Title**, **Revision**, **Status**, **Requested by**, und **Created**. Auf kleineren Bildschirmen erscheinen sekundäre Details unterhalb des Titels. Öffnen Sie eine Aufgabe, um **From organization** zu sehen, wenn eine Organisation erfasst wird.

Verwenden Sie den Breadcrumb **Tasks** über dem Aufgabentitel, um zur Liste zurückzukehren.

E-Mail-adressierte Aufgaben einer Organisation kommen in Personal an. Sie gewähren Ihnen keinen Zugriff auf den Arbeitsbereich dieser Organisation. Organisationsdelegierte können auch autorisierte Aufgaben ausführen; siehe [Delegationen](delegations.md).

## Geben Sie die erforderlichen Informationen ein. {#provide-the-required-information}

Verwenden Sie unterhalb der Aufgabenzusammenfassung **Your response**, um Ihre Entscheidung auszuwählen und bei Bedarf Anhänge, einen Kommentar und eine Signatur anzugeben.

Verwenden Sie die für Sie angebotene Aktion Aufgabe. Der Workflow erfordert möglicherweise einen Kommentar, einen Antwortanhang, eine elektronische Signatur oder eine Kombination davon. Füllen Sie vor dem Absenden alle erforderlichen Felder aus. Eine negative Entscheidung erfordert einen Kommentar, der das Ergebnis erläutert.

Für eine Unterschrift überprüfen Sie Ihr **Legal name**, geben Sie gegebenenfalls **Representation details** ein und geben Sie Ihre Unterschrift ab. Eine [gespeicherte Profilsignatur](profile.md) kann die Zeichnung vorab ausfüllen; Überprüfen Sie es für diese Entscheidung.

## Genehmigen, ablehnen oder Änderungen anfordern {#approve-reject-or-request-changes}

Die Antwortoptionen hängen vom **Action** des Schritts ab. Dies sind einige häufige Optionen:

| Schrittaktion | Positive Resonanz | Negative Antwort |
| --- | --- | --- |
| Approve | **Approve**|**Reject** |
| Review | **Review**|**Request changes** |
| Sign | **Sign**|**Decline** |

Eine negative Antwort erfordert einen Kommentar und stoppt die Anfrage mit einem erfolglosen Ergebnis. Wählen Sie beispielsweise **Request changes** für eine Überprüfungsaufgabe aus und erläutern Sie, welcher Teil des Dokuments aktualisiert werden muss. Der Anforderer kann dann [eine berechtigte Anfrage überarbeiten und erneut einreichen](track-requests.md#revise-and-resubmit).

Verwenden Sie [Chat](discussions.md), um die Anfrage zu klären, bevor Sie Ihre Aktion aufzeichnen. Eine Chat-Nachricht schließt die Aufgabe nicht ab. Eine im Chat gesendete Datei erfüllt nicht **Require an attachment**; Fügen Sie diese Datei unter **Your response** hinzu. Siehe [Dateien und Anhänge](files.md).

## Senden Sie die Entscheidung {#submit-the-decision}

Wählen Sie die Aktion aus, die Ihrer Entscheidung entspricht, einschließlich eines negativen Ergebnisses, wenn die Aufgabe eines bietet. Überprüfen Sie die Entscheidung und eine etwaige Bestätigung, bevor Sie sie absenden. Warten Sie auf die Erfolgsrückmeldung.

Ihre aufgezeichnete Aktion wird Teil des Anfrageverlaufs. Nach einer erfolgreichen Antwort kann der Schritt abhängig von seiner Abschlussregel auf andere Beauftragte warten oder sofort fortfahren. Eine negative Antwort beendet den Workflow mit einem fehlgeschlagenen Ergebnis.

## Später zurückkehren {#return-later}

Beim Verlassen der Aufgabenseite wird eine nicht übermittelte Antwort verworfen, ohne um Bestätigung zu bitten. Schließen Sie die Aufgabe ab, um Ihre Entscheidung aufzuzeichnen.

Öffnen Sie die Aufgabe erneut, um die aufgezeichnete Aktion und den Kontext zu überprüfen. Aufgaben können nicht mehr abgeschlossen werden, wenn sie abgebrochen, übersprungen, durch eine Überarbeitung ersetzt oder von einem anderen berechtigten Teilnehmer abgeschlossen werden. Aktualisieren Sie die Aufgabe, bevor Sie eine Aktion nach einem Fehler erneut versuchen.

Der Statuschip in der Kopfzeile der Aufgabenkarte zeigt den aktuellen Status oder die aufgezeichnete Aktion an, z. B. „Ausstehend“, „Signiert“ oder „Abgelehnt“.
