# Genehmigungsstatus verfolgen und Anfragen überarbeiten {#track-and-revise-requests}

Um den Genehmigungsstatus eines Dokuments zu überprüfen, öffnen Sie **Requests** in dem Arbeitsbereich, der die Anfrage besitzt. Nutzen Sie **Personal**, Ihren Arbeitsbereich für Ihre eigenen Anfragen, für Arbeiten, die Sie persönlich gesendet haben. Wählen Sie für Arbeiten, die im Namen einer Organisation gesendet werden, diese Organisation aus.

Verwenden Sie die verfügbaren Filter, um die Anfrage zu finden, und öffnen Sie dann deren Details, um Dateien, Schritte, Teilnehmer und aufgezeichnete Aktionen zu überprüfen. Für Ihnen zugewiesene Aktionen öffnen Sie stattdessen **Tasks**; siehe [Eine Aufgabe abschließen](complete-a-task.md).

## Fortschritt und Ergebnisse lesen {#read-progress-and-outcomes}

Workflow-Schritte werden unterhalb der Anforderungszusammenfassung angezeigt. Die Überschrift jedes Schritts zeigt seine Nummer und Aktion an, z. B. **Step 1 · Approve**. Erweitern Sie die Überschrift, um die Abschlussregel, die Sichtbarkeit, die Anforderungen und die ursprünglichen Beauftragten anzuzeigen. Die zugewiesenen Symbole kennzeichnen Teams, Mitarbeiter und E-Mail-Adressen. Aufgabenkarten bleiben sichtbar, wenn Sie die Schrittdetails reduzieren.

Erweitern Sie eine Aufgabe, um **Assigned via** anzuzeigen, wenn sie aus einer Teamaufgabe stammt. Ein **Upcoming task** zeigt jemanden an, dessen Aufgabe noch nicht begonnen hat.**From organization** gibt beim Anzeigen für eine Aufgabe den Namen der aufgezeichneten Organisation an. Personal ist ein Arbeitsbereich, keine Organisation.

Der Statuschip im Header jeder Anforderungs- oder Aufgabenkarte zeigt den aktuellen Status an, auch wenn die Karte minimiert ist.

| Staat | Bedeutung |
| --- | --- |
| Pending | Eingereichte Arbeit wartet auf Fortschritt |
| Started | Der Workflow wird ausgeführt |
| Completed — Succeeded | Der Workflow wurde erfolgreich abgeschlossen |
| Completed — Failed | Der Workflow wurde mit einem erfolglosen Ergebnis abgeschlossen |
| Canceled | Die Anfrage wurde gestoppt |
| Superseded | Diese Anfrage wurde durch eine neuere Revision ersetzt. |

Einzelne Aufgabenaktionen können spezifischere Bezeichnungen haben, z. B. „Signiert“ oder „Abgelehnt“. Eine übersprungene Aufgabe bedeutet nicht, dass der Teilnehmer eine Entscheidung getroffen hat; Ein anderes Ergebnis könnte den Schritt bereits gelöst haben. Automatisch abgeschlossene Anfragen und übersprungene oder abgebrochene Aufgaben zeigen ihren Status und die Fertigstellungszeit ohne ein **Completed by**-Feld an.

## Stornieren Sie eine Anfrage {#cancel-a-request}

Öffnen Sie eine ausstehende oder gestartete Anfrage, zu deren Verwaltung Sie berechtigt sind, wählen Sie **Cancel request** und bestätigen Sie. Bei einer Stornierung wird der Workflow gestoppt. Öffnen Sie die Anfrage erneut, um ihren endgültigen Status zu überprüfen, bevor Sie die Teilnehmer kontaktieren.

## Überarbeiten Sie und reichen Sie sie erneut ein. {#revise-and-resubmit}

Überarbeiten Sie berechtigte Anfragen entweder in Personal oder einer Organisation.

Ein Prüfer kann beispielsweise **Request changes** auswählen und erklären, dass ein Angebot einen falschen Preis enthält. Verwenden Sie **Resubmit**, um den Vorschlag zu ersetzen und eine neue Überprüfung zu starten. Durch das Hinzufügen einer Datei zu [Chat](discussions.md) werden die aktuellen Überprüfungsdateien der Anfrage nicht ersetzt.

1. Öffnen Sie eine berechtigte Anfrage und wählen Sie **Resubmit**.
2. Überprüfen Sie die Dateien, Anweisungen und Workflow-Schritte der vorherigen Revision.
3. Aktualisieren Sie die Dateien, Anweisungen und Schritte für die neue Revision.
4. Überprüfen Sie die Teilnehmer und wählen Sie **Submit**.

Eine erneute Einreichung erstellt eine neue Revision und ersetzt die vorherige Anfrage. Die Aktion wird nur für berechtigte ausstehende, begonnene oder abgeschlossene Anfragen angeboten, die nicht erfolgreich waren und keine neuere Revision haben. Eine erfolgreich abgeschlossene Anfrage kann mit dieser Aktion nicht erneut übermittelt werden.

Die neue Revision beginnt ihren Workflow mit dem ersten Schritt. Frühere Entscheidungen bleiben auf der vorherigen Revision und ihren Belegen gespeichert; Sie schließen Aufgaben in der neuen Revision nicht ab. Überprüfen Sie jeden Schritt und jeden Teilnehmer, bevor Sie ihn erneut einreichen.

Verwenden Sie **Show revision changes**, sofern vorhanden, um hinzugefügte, ersetzte und entfernte Dateien zu überprüfen. Ersetzte oder gelöschte Dateien bleiben für die Überarbeitung im Kontext und sind nicht Teil der aktuell zu überprüfenden Dateien.

## Ergebnis beibehalten {#preserve-the-result}

[Receipts](receipts.md) zeichnen das Ergebnis der Anfrage und die aufgezeichneten Aktionen jedes Teilnehmers auf, vorbehaltlich der Schrittsichtbarkeit. Sie werden erstellt, wenn eine Anfrage abgeschlossen, abgebrochen oder durch eine neue Revision ersetzt wird. Überprüfen Sie [Aufbewahrung und Löschung](retention.md), bevor Sie eine Anfrage entfernen oder sich auf einen langfristigen Zugriff verlassen.

Eine neuere Revision verhindert das Löschen der Anfrage, auf die sie verweist. Planen Sie zuerst das Löschen der neuesten Revision und warten Sie dann auf die Hintergrundbereinigung, bevor Sie die Vorgängerversion entfernen. Durch das Entfernen einer Anfrage werden die Belege der Teilnehmer nicht entfernt.
