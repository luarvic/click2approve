# Dateien zu Genehmigungsanfragen und Aufgaben hinzufügen {#files-and-attachments}

Sie können Dateien an eine Dokumentgenehmigungsanfrage, die Entscheidung eines Teilnehmers oder eine Chat-Nachricht anhängen. Jeder Ort hat einen anderen Zweck. Überprüfen Sie, wo Sie eine Datei anhängen, damit sie Teil des benötigten Datensatzes wird.

| Sie möchten… | Hängen Sie die Datei hier an |
| --- | --- |
| Senden Sie ein Dokument zur Überprüfung | **Files to review** beim Erstellen der Anfrage |
| Senden Sie eine Datei mit Ihrer Aufgabenantwort | **Your response** zur Aufgabe |
| Geben Sie zusätzliche Informationen weiter oder stellen Sie eine Frage | **Chat** für die Anfrage oder Aufgabe |

Jeder Anhang kann bis zu **50 MiB** (52.428.800 Byte) groß sein. Dies gilt für Antrags-, Entscheidungs- und Diskussionsanhänge. Es gelten auch Workspace-Speicher- und Token-Beschränkungen.

## Dateien anfordern {#request-files}

Fügen Sie die Dokumente hinzu, die Teilnehmer beim [Erstellen einer Anfrage überprüfen müssen](create-a-request.md). Verwenden Sie erkennbare Dateinamen und überprüfen Sie die ausgewählten Dateien vor dem Absenden.

Öffnen Sie einen Dateinamen, um die verfügbare Vorschau- oder Download-Aktion zu verwenden. Die Vorschauunterstützung hängt vom Dateiformat und Browser ab. Wenn das Dokument in der Vorschau nicht angezeigt werden kann, laden Sie es herunter und verwenden Sie eine geeignete Anwendung.

## Entscheidungsanhänge {#decision-attachments}

Fügen Sie auf Anfrage Antwortdateien im Aufgabenaktionsbereich hinzu. Ein mit **Require an attachment** gekennzeichneter Schritt kann ohne die erforderliche Antwortdatei nicht abgeschlossen werden.

Entscheidungsanhänge werden mit der aufgezeichneten Aufgabenaktion angezeigt. Das Hochladen derselben Datei in den Chat erfüllt nicht die Anhanganforderung einer Aufgabe.

## Diskussionsanhänge {#discussion-attachments}

Hängen Sie unterstützendes Material an eine [Chat-Nachricht](discussions.md) an, wenn Sie die Anfrage klären müssen. Berücksichtigen Sie das Diskussionspublikum, bevor Sie es teilen.

## Überarbeitete Dateien {#revised-files}

Eine Überarbeitung kann Anforderungsdateien hinzufügen, entfernen oder ersetzen. Überprüfen Sie die aktuelle Dateiliste und verwenden Sie **Show revision changes** als Kontext. Die angezeigten ersetzten und entfernten Dateien sind keine aktuellen Überprüfungsdokumente.

## Probleme beim Hochladen {#upload-problems}

Warten Sie, bis die Uploads abgeschlossen sind, bevor Sie sie absenden. Wenn ein Upload abgelehnt wird, lesen Sie den Fehler und überprüfen Sie die [Nutzungsbeschränkungen der Datei und des Arbeitsbereichs](usage.md). Vermeiden Sie wiederholte Übermittlungen, während eine Anfrage noch bearbeitet wird. Siehe [Fehlerbehebung](troubleshooting.md) für fehlgeschlagene Aktionen.

## Tokens und Speicher {#tokens-and-storage}

Uploads sowie das Anzeigen und Herunterladen von Dateien verbrauchen Tokens. Die Dateigröße zählt außerdem zum separaten Speicherlimit. Bei Dateien aus Aufgaben und Diskussionen trägt der ursprüngliche Workflow-Arbeitsbereich die Kosten; sonst wird der ausgewählte Arbeitsbereich belastet. Uploads werden erst nach erfolgreichem Abschluss berechnet. Gleichzeitige Übertragungen können zu einem negativen Token-Guthaben führen. Bei abgebrochenen Downloads zählen die bereits übertragenen Dokumentbytes. Siehe [Nutzung und Token](usage.md).
