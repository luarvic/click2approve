# Arquivos e anexos para aprovações de documentos {#files-and-attachments}

Você pode anexar arquivos a uma solicitação de aprovação de documento, a uma decisão de um participante ou a uma mensagem de bate-papo. Cada lugar tem um propósito diferente. Verifique onde você anexa um arquivo para que ele se torne parte do registro que você precisa.

| Você quer… | Anexe o arquivo aqui |
| --- | --- |
| Envie um documento para as pessoas analisarem | **Files to review** ao criar a solicitação |
| Envie um arquivo com a resposta da sua tarefa | **Your response** na tarefa |
| Compartilhe informações extras ou faça uma pergunta | **Chat** na solicitação ou tarefa |

Cada anexo pode ter até **50 MiB** (52.428.800 bytes). Isso se aplica a anexos de solicitação, decisão e discussão. Limites de armazenamento e token do espaço de trabalho também se aplicam.

## Arquivos de solicitação {#request-files}

Adicione os documentos que os participantes devem revisar ao [criar uma solicitação](create-a-request.md). Use nomes de arquivo reconhecíveis e verifique os arquivos selecionados antes de enviar.

Abra um nome de arquivo para usar sua visualização disponível ou ação de download. O suporte à visualização depende do formato do arquivo e do navegador. Se uma visualização não puder exibir o documento, baixe-o e use um aplicativo adequado.

## Anexos de decisão {#decision-attachments}

Anexe arquivos de resposta na área de ação da tarefa quando solicitado. Uma etapa marcada como **Require an attachment** não pode ser concluída sem o arquivo de resposta necessário.

Anexos de decisão aparecem com a ação da tarefa registrada. O upload do mesmo arquivo para o Chat não atende aos requisitos de anexo de uma tarefa.

## Anexos de discussão {#discussion-attachments}

Anexe material de apoio a uma [mensagem do Chat](discussions.md) quando precisar esclarecer a solicitação. Considere o público da discussão antes de compartilhá-la.

## Arquivos revisados  {#revised-files}

Uma revisão pode adicionar, remover ou substituir arquivos de solicitação. Revise a lista de arquivos atual e use **Show revision changes** para contexto. Arquivos substituídos e removidos mostram que não há documentos de revisão atuais.

## Problemas de upload {#upload-problems}

Aguarde a conclusão dos uploads antes de enviar. Se um upload for rejeitado, leia o erro e verifique os [limites de uso do arquivo e do espaço de trabalho](usage.md). Evite enviar repetidamente enquanto uma solicitação ainda está sendo processada. Consulte [Solução de problemas](troubleshooting.md) para ações com falha.

## Tokens e armazenamento {#tokens-and-storage}

Enviar arquivos, visualizar prévias e baixar arquivos consome tokens. O tamanho dos arquivos também conta para o limite separado de armazenamento. Os arquivos de tarefas e discussões são cobrados do espaço de trabalho que originou o fluxo; os demais envios usam o espaço selecionado. Envios só são cobrados após a conclusão bem-sucedida. Transferências simultâneas podem deixar o saldo de tokens negativo. Em downloads interrompidos, são cobrados os bytes do documento já transferidos. Consulte [Uso e tokens](usage.md).
