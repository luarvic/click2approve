# Aggiungere file alle richieste e alle attività di approvazione {#files-and-attachments}

Puoi allegare file a una richiesta di approvazione di un documento, a una decisione di un partecipante o a un messaggio di chat. Ogni luogo ha uno scopo diverso. Controlla dove alleghi un file in modo che diventi parte del record che ti serve.

| Vuoi… | Allega il file qui |
| --- | --- |
| Invia un documento affinché le persone possano esaminarlo | **Files to review** durante la creazione della richiesta |
| Invia un file con la risposta all'attività | **Your response** sull'attività |
| Condividi informazioni aggiuntive o fai una domanda | **Chat** sulla richiesta o attività |

Ogni allegato può contenere fino a **50 MiB** (52.428.800 byte). Questo vale per gli allegati di richiesta, decisione e discussione. Si applicano anche limiti di archiviazione e token dell'area di lavoro.

## File di richiesta {#request-files}

Aggiungi i documenti che i partecipanti devono rivedere quando [creano una richiesta](create-a-request.md). Utilizza nomi file riconoscibili e controlla i file selezionati prima di inviarli.

Apri un nome file per utilizzare l'anteprima disponibile o l'azione di download. Il supporto dell'anteprima dipende dal formato del file e dal browser. Se un'anteprima non può visualizzare il documento, scaricalo e utilizza un'applicazione adatta.

## Allegati decisione {#decision-attachments}

Allega file di risposta nell'area di azione dell'attività quando richiesto. Un passaggio contrassegnato **Require an attachment** non può essere completato senza il file di risposta richiesto.

Gli allegati alla decisione vengono visualizzati con l'azione dell'attività registrata. Il caricamento dello stesso file su Chat non soddisfa i requisiti di allegato di un'attività.

## Allegati discussione {#discussion-attachments}

Allega materiale di supporto a un [messaggio di chat](discussions.md) quando è necessario chiarire la richiesta. Considera il pubblico della discussione prima di condividerla.

## File revisionati {#revised-files}

Una revisione può aggiungere, rimuovere o sostituire i file di richiesta. Esamina l'elenco dei file corrente e utilizza **Show revision changes** per il contesto. I file sostituiti e rimossi visualizzati non sono documenti di revisione correnti.

## Problemi di caricamento {#upload-problems}

Attendere il completamento dei caricamenti prima di inviare. Se un caricamento viene rifiutato, leggere l'errore e controllare i [limiti di utilizzo del file e dell'area di lavoro](usage.md). Evita di inviare ripetutamente mentre una richiesta è ancora in elaborazione. Vedi [Risoluzione dei problemi](troubleshooting.md) per le azioni non riuscite.

## Token e spazio di archiviazione {#tokens-and-storage}

Il caricamento, l’anteprima e il download dei file consumano token. La dimensione dei file incide anche sul limite di archiviazione, che è separato. Per i file di attività e discussioni paga lo spazio di lavoro da cui proviene il flusso; gli altri caricamenti usano quello selezionato. I caricamenti vengono addebitati solo se completati correttamente. I trasferimenti simultanei possono portare il saldo dei token sotto zero. Se un download si interrompe, vengono addebitati i byte del documento già trasferiti. Vedi [Utilizzo e token](usage.md).
