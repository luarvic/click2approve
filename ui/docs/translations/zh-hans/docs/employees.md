# 员工和角色 {#employees-and-roles}

员工将用户帐户连接到组织，并提供用于分配和审核记录的身份。

!!! info“仅限组织”
    选择一个组织以查看其员工。所有者和管理员可以添加员工并管理他们的访问权限。

## 添加员工 {#add-an-employee}

所有者和管理员可以打开 **Employees**，启动新员工，然后输入他们的电子邮件、姓名、职位、角色和团队。保存员工，然后检查其状态。

电子邮件标识应接收员工访问权限的帐户。保存前检查一下。员工的组织名称和职位可能与其个人资料不同。

电子邮件尚未注册的员工以 **Pending**开头。使用该电子邮件注册即可激活会员资格。添加已注册的帐户会创建**Active** 员工。

## 角色 {#roles}

|角色 |组织权限 |
| --- | --- |
| User (member) |参与授权工作流程，查看员工、团队和委派目录，并管理自己的模板 |
| Admin |管理员工、团队、授权、计费和保留 |
| Owner |行政管理加上安排组织删除的权限 |

角色不会向其他组织授予访问权限。请求和任务可见性还取决于参与、团队关系和委派。模板默认是私有的，可以共享给其他组织成员查看和使用。只有模板的创建者可以编辑或删除它，包括当其他成员是所有者或管理员时。

结果记录访问遵循结果记录所有权，无论员工角色如何。所有者和管理员只能查看、共享和删除发给自己的结果记录。请参阅[结果记录和验证](receipts.md)。

## 员工状态 {#employee-status}

| Status |含义 |
| --- | --- |
| Pending |会员资格尚未生效 |
| Active |员工访问已激活 |
| Disabled |员工访问已被禁用 |

所有者和管理员可以编辑允许的员工详细信息、团队成员资格和 **Active** 设置。当某人不应再为组织行事时，禁用访问权限非常有用。

## 删除员工 {#remove-an-employee}

仅在应删除员工时才使用可用的删除操作。现有的引用可以防止删除；首先读取验证消息并解决相关关系。当必须保留历史关系时，禁用访问权限可能是适当的。

在更改成员资格之前，请查看依赖于该员工的[团队](teams.md) 和[委派](delegations.md)。
