# 创建文档审批请求 {#create-a-request}

要发送文档以供审批，请创建 **请求**。它包含要查看的文件、说明以及告诉每个参与者该做什么的步骤。您可以请求批准、审核或电子签名。

首先选择正确的工作区。使用 **Personal**（您自己的请求的工作区)以您自己的名义发送工作。选择一个组织代表其发送作业。您的工作区决定谁拥有该请求以及您可以使用哪些受派人类型。 **受派人**是您要求执行某个步骤的个人或团队。

## 撰写请求 {#compose-the-request}

1. [打开应用程序](/app/)，选择您的工作区，然后选择主菜单 **Work**组顶部的**New request**。
2. 在组织中，选择 **Custom**或**From template**。对于模板，选择它并继续进入请求编辑器。
3. 输入具体的 **Title**，例如“批准更新的供应商协议”。
4. 添加 **Description** 解释目的、背景和预期结果。
5. 附上[参与者应查看的文件](files.md)。
6. 添加并配置[工作流程步骤](workflow-steps.md)。

**Request details**卡片对标题、**Files to review** 和说明进行分组。配置其下方的工作流程步骤。

Personal 请求使用电子邮件受派人。

!!! info“组织受派人”
    在组织中，您还可以向该组织的员工和团队分配步骤。

## 示例：发送提案以供批准和签名 {#example-send-a-proposal-for-approval-and-signature}

1. 在 **Files to review** 下添加提案。
2. 添加将 **Action**设置为**Approve** 的步骤，然后添加审阅者的电子邮件地址。
3. 选择**Add step**并将其**Action**设置为**Sign**。添加客户的电子邮件地址并启用 **Require an electronic signature**。
4. 为每个步骤写下**Instructions**，以便双方都知道要检查什么。

审批步骤成功后客户端收到任务。如果需要多人先审批，请将他们添加到审批步骤并启用**All assignees must complete**。请参阅[配置工作流程步骤](workflow-steps.md) 了解完成规则。

## 查看并提交 {#review-and-submit}

检查文件、步骤顺序、操作、说明、参与者、完成规则、可见性和其他要求。如需绘制签名，请勾选**Require an electronic signature**；单独选择 **Sign**操作并不能启用它。然后选择**Submit** 并在离开页面之前等待确认。

如果字段突出显示，请更正它们并再次提交。如果计划限制阻止提交，请检查[使用情况](usage.md) 或向组织所有者或管理员寻求帮助。

如果您的组织员工姓名不完整，则会出现一条警告，说明该姓名将如何显示在记录中。选择 **Go back**进行更正，或选择**Proceed anyway** 以当前名称提交。组织员工详细信息与您的个人资料分开管理。

撰写自定义新组织请求时，**Save template** 会根据标题、说明和步骤创建私有模板。它应用模板验证规则并且不会取代提交请求。从模板启动的请求和请求修订不提供此操作。请参阅[工作流程模板](templates.md)。

## 提交 后 {#after-submission}

打开 **Requests** 并选择请求以跟踪其进度。当工作流程到达他们的步骤时，参与者就会行动。通知发送遵循每个收件人的偏好。

使用[跟踪和修改请求](track-requests.md) 了解结果、取消和修改。离开或取消撰写屏幕会放弃编辑而不要求确认。请求草稿不会保存。
