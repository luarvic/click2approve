# 审核、批准或签署文档 {#complete-a-task}

**任务**要求您执行文档审批请求的一个步骤。打开**Tasks** 以审阅、批准或签署分配给您的文档。在记录您的决定之前，请阅读当前文档和说明。

## 找到任务 {#find-the-task}

1. [使用任务发送到的帐户打开应用程序](/app/)。
2. 在工作区选择器中，为发送到您的电子邮件地址的任务选择 **Personal**。 Personal 是直接发送给您的您自己的请求和任务的工作区。对于员工或团队分配，请选择组织。
3. 打开 **Tasks** 并选择等待您操作的任务。
4. 阅读标题、请求者、说明、步骤说明和当前文件。

对于团队分配，**Assigned to**使用员工图标显示接收任务的单个员工。在**Workflow**选项卡中，展开步骤标题以查看其原始受派人和设置。任务卡在标题下方可见。展开团队创建的任务可查看**Assigned via**，它标识团队。

任务和请求列表使用相同的列和宽度：**#**、**Title**、**Revision**、**Status**、**Requested by**和**Created**。在较小的屏幕上，次要详细信息显示在标题下方。打开任务以在记录组织时查看 **From organization**。

使用任务标题上方的 **Tasks** 面包屑返回到列表。

来自组织的电子邮件地址任务将到达 Personal。他们不允许您访问该组织的工作空间。组织代表还可以执行授权任务；请参阅[工作委托](delegations.md)。

## 提供所需信息 {#provide-the-required-information}

在任务摘要下方，使用 **Your response** 选择您的决定，并在需要时提供附件、评论和签名。

使用为您提供的操作任务。工作流程可能需要评论、响应附件、电子签名或这些的组合。提交前填写所有必填字段。否定的决定需要评论来解释结果。

如需签名，请检查您的 **Legal name**，在相关时输入 **Representation details**，然后提供您的签名。 [已保存的个人资料签名](profile.md)可以预先填写图纸；查看此决定。

## 批准、拒绝或请求更改 {#approve-reject-or-request-changes}

响应选择取决于步骤的 **Action**。以下是一些常见的选择：

|步骤动作|积极响应 |否定回应 |
| --- | --- | --- |
| Approve | **Approve**|**Reject** |
| Review | **Review**|**Request changes** |
| Sign | **Sign**|**Decline** |

否定响应需要评论并以不成功的结果停止请求。例如，在审阅任务中选择 **Request changes** 并说明文档的哪一部分需要更新。然后，请求者可以[修改并重新提交符合条件的请求](track-requests.md#revise-and-resubmit)。

在记录您的操作之前，使用[聊天](discussions.md)澄清请求。聊天消息并不能完成任务。聊天中发送的文件不满足**Require an attachment**；将该文件添加到 **Your response** 下。请参阅[文件和附件](files.md)。

## 提交决定 {#submit-the-decision}

选择与您的决定相匹配的操作，包括任务提供负面结果时的操作。提交前检查决定和任何确认。等待成功反馈。

您记录的操作将成为请求历史记录的一部分。成功响应后，该步骤可能会等待其他受派人或立即继续，具体取决于其完成规则。否定响应将以失败结果结束工作流程。

## 稍后返回 {#return-later}

离开任务页面会丢弃未提交的响应，而不要求确认。完成任务以记录您的决定。

重新打开任务以查看记录的操作和上下文。当任务被取消、跳过、被修订取代或由其他符合条件的参与者完成时，任务可能无法完成。在发生错误后重试操作之前刷新任务。

任务卡标题中的状态芯片显示其当前状态或记录的操作，例如待处理、已签名或已拒绝。
