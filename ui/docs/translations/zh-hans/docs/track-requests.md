# 跟踪审批状态并修订申请 {#track-and-revise-requests}

在申请所属工作区打开 **Requests**查看审批状态。以个人名义发送的工作使用**Personal**；代表组织发送的工作则选择该组织。

用筛选找到申请，打开详情检查文件、步骤、参与者和操作。要处理分配给自己的工作，请打开 **Tasks**，见[完成任务](complete-a-task.md)。

## 查看进度和结果 {#read-progress-and-outcomes}

步骤位于申请摘要下。标题显示编号和操作，如 **Step 1 · Approve**。展开可查看完成规则、可见范围、要求和原始受派人；图标区分团队、员工及邮箱。折叠步骤详情时任务卡片仍可见。

展开来自团队的任务，可看到 **Assigned via**。**Upcoming task** 表示该人的任务尚未开始。

任务中的 **From organization** 表示记录的组织。Personal 是工作区，不是组织。

申请和任务卡片标题的状态标签在折叠时也显示当前状态。

| 状态 | 含义 |
| --- | --- |
| Pending | 已提交，等待推进 |
| Started | 工作流正在执行 |
| Completed — Succeeded | 工作流成功完成 |
| Completed — Failed | 工作流以失败结果结束 |
| Canceled | 申请已停止 |
| Superseded | 已被较新修订替代 |

任务可显示 Signed、Rejected 等更具体的操作。任务被跳过不代表该人已作决定，可能是其他结果已完成步骤。自动完成的申请，以及跳过或取消的任务，显示状态和结束时间，不显示 **Completed by**。

## 取消申请 {#cancel-a-request}

打开有权管理的待处理或进行中申请，选择 **Cancel request** 并确认。取消会停止工作流。联系参与者前，请重新打开检查最终状态。

## 修订并重新提交 {#revise-and-resubmit}

Personal 及组织中的符合条件申请均可修订。

例如，审核人通过 **Request changes**指出提案价格有误。用**Resubmit** 替换提案并重新审核。在[聊天](discussions.md)添加附件不会替换当前审核文件。

1. 打开符合条件申请，选择 **Resubmit**。
2. 检查旧修订的文件、说明和步骤。
3. 为新修订更新文件、说明和步骤。
4. 核对参与者后选择 **Submit**。

重新提交创建新修订并替代旧申请。仅未成功、没有更新版本的符合条件待处理、进行中或已结束申请可用。成功完成的申请不能用此操作重新提交。

新修订从第一步重新运行。旧决定仍保存在旧修订及结果记录中，不会完成新版本任务。再次提交前请逐一检查人员和步骤。

有 **Show revision changes** 时，可检查新增、替换和移除的文件。旧文件仍提供版本上下文，但不属于当前待审核文件。

## 保存结果 {#preserve-the-result}

[结果记录](receipts.md)按步骤可见范围保存结果及参与者操作，在申请完成、取消或被新版本替代时生成。删除申请或依赖长期访问前，请阅读[保留与删除](retention.md)。

新修订引用旧申请时，旧申请不能删除。先安排删除最新修订，等待后台清理后再删前一个。删除申请不会删除参与者的结果记录。
