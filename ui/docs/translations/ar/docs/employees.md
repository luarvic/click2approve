# إدارة الموظفين وأدوارهم في مساحة العمل {#employees-and-roles}

يقوم الموظفون بربط حسابات المستخدمين بالمؤسسة وتوفير الهويات المستخدمة للمهام وسجلات التدقيق.

!!! info "المؤسسة فقط"
    حدد مؤسسة لعرض موظفيها. يمكن للمالكين والمسؤولين إضافة موظفين وإدارة وصولهم.

## إضافة موظف {#add-an-employee}

يمكن للمالكين والمسؤولين فتح **Employees** وبدء موظف جديد وإدخال البريد الإلكتروني والاسم والمنصب والدور والفرق. احفظ الموظف، ثم تحقق من حالته.

يحدد البريد الإلكتروني الحساب الذي يجب أن يحصل على حق وصول الموظف. التحقق من ذلك قبل الحفظ. يمكن أن يختلف اسم مؤسسة الموظف ومنصبها عن ملفه الشخصي.

يبدأ الموظف الذي لم يتم تسجيل بريده الإلكتروني بعد **Pending**. التسجيل بهذا البريد الإلكتروني ينشط العضوية. تؤدي إضافة حساب مسجل بالفعل إلى إنشاء موظف **Active**.

## الأدوار {#roles}

| الدور | أذونات المؤسسة |
| --- | --- |
| User (member) | المشاركة في سير العمل المعتمد، وعرض أدلة الموظفين والفريق والتفويض، وإدارة القوالب الخاصة بهم |
| Admin | إدارة الموظفين والفرق والتفويضات وإعداد الفواتير والاحتفاظ |
| Owner | الإدارة الإدارية بالإضافة إلى سلطة جدولة حذف المؤسسة |

لا تمنح الأدوار حق الوصول إلى المؤسسات الأخرى. تتبع رؤية الطلب والمهمة أيضًا المشاركة وعلاقات الفريق والتفويض. تكون القوالب خاصة بشكل افتراضي ويمكن مشاركتها مع أعضاء المؤسسة الآخرين لعرضها واستخدامها. يمكن لمنشئ القالب فقط تعديله أو حذفه، بما في ذلك عندما يكون عضو آخر مالكًا أو مسؤولًا.

يتبع الوصول إلى الإيصال ملكية الإيصال، بغض النظر عن دور الموظف. يمكن للمالكين والمسؤولين عرض ومشاركة وحذف الإيصالات الصادرة لأنفسهم فقط. راجع [الإيصالات والتحقق](receipts.md).

## حالة الموظف {#employee-status}

| Status | المعنى |
| --- | --- |
| Pending | العضوية لم تصبح نشطة بعد |
| Active | وصول الموظف نشط |
| Disabled | تم تعطيل وصول الموظف |

يمكن للمالكين والمسؤولين تعديل تفاصيل الموظف المسموح بها، وعضويات الفريق، وإعداد **Active**. يكون تعطيل الوصول مفيدًا عندما يتوقف الشخص عن العمل لصالح المؤسسة.

## إزالة موظف {#remove-an-employee}

استخدم إجراء الحذف المتاح فقط عندما يجب إزالة الموظف. المراجع الموجودة يمكن أن تمنع الحذف؛ اقرأ رسالة التحقق من الصحة وقم بحل العلاقة ذات الصلة أولاً. يمكن أن يكون تعطيل الوصول مناسبًا عندما يجب أن تظل العلاقات التاريخية.

قبل تغيير العضوية، قم بمراجعة [الفرق](teams.md) و[التفويضات](delegations.md) التي تعتمد على هذا الموظف.
