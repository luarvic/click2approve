# متابعة حالة الموافقة ومراجعة الطلبات {#track-and-revise-requests}

لفحص حالة المستند، افتح **Requests** في مساحة الطلب. استخدم **Personal** للعمل الذي أرسلته باسمك، واختر المؤسسة للعمل المرسل نيابة عنها.

ابحث بالفلاتر وافتح التفاصيل لمراجعة الملفات والخطوات والمشاركين والإجراءات المسجلة. أما الإجراءات المسندة إليك فافتح **Tasks**؛ راجع [إتمام مهمة](complete-a-task.md).

## قراءة التقدم والنتائج {#read-progress-and-outcomes}

تظهر الخطوات أسفل ملخص الطلب، ويعرض عنوان كل منها رقمها وإجراءها، مثل **Step 1 · Approve**. وسّعه لرؤية قاعدة الإتمام والرؤية والمتطلبات والمكلّفين الأصليين. تميز الرموز الفرق والموظفين والبريد. تبقى بطاقات المهام ظاهرة عند طي تفاصيل الخطوة.

وسّع مهمة لعرض **Assigned via** إذا نشأت عن إسناد لفريق. وتُظهر **Upcoming task** شخصًا لم تبدأ مهمته بعد.

يسمي **From organization** المؤسسة المسجلة للمهمة. Personal مساحة عمل وليست مؤسسة.

تعرض شارة الحالة في رأس بطاقة الطلب أو المهمة حالتها الحالية حتى عندما تكون مطوية.

| الحالة | معناها |
| --- | --- |
| Pending | العمل المرسل ينتظر التقدم |
| Started | سير العمل جارٍ |
| Completed — Succeeded | اكتمل العمل بنجاح |
| Completed — Failed | اكتمل بنتيجة غير ناجحة |
| Canceled | أُوقف الطلب |
| Superseded | حلّت مراجعة أحدث محل الطلب |

قد تحمل إجراءات المهام أسماء أدق مثل Signed أو Rejected. لا تعني المهمة المتخطاة أن المشارك اتخذ قرارًا؛ فقد حسمت نتيجة أخرى الخطوة. تعرض الطلبات المكتملة تلقائيًا والمهام المتخطاة أو الملغاة الحالة والوقت دون **Completed by**.

## إلغاء طلب {#cancel-a-request}

افتح طلبًا معلقًا أو بدأ بالفعل وتملك صلاحية إدارته، واختر **Cancel request** وأكّد. يوقف الإلغاء سير العمل. أعد فتح الطلب لفحص حالته النهائية قبل التواصل مع المشاركين.

## المراجعة وإعادة الإرسال {#revise-and-resubmit}

يمكن مراجعة الطلبات المؤهلة في Personal والمؤسسات.

مثلًا، قد يختار مراجع **Request changes** لوجود سعر خاطئ في عرض. استخدم **Resubmit** لاستبداله وبدء مراجعة جديدة. لا يغير إرفاق ملف في [المحادثة](discussions.md) ملفات المراجعة الحالية للطلب.

1. افتح طلبًا مؤهلًا واختر **Resubmit**.
2. راجع ملفات النسخة السابقة وتعليماتها وخطواتها.
3. حدّث الملفات والتعليمات والخطوات للنسخة الجديدة.
4. تحقق من المشاركين واختر **Submit**.

ينشئ الإرسال مراجعة جديدة تحل محل الطلب السابق. يتوفر فقط للطلبات المؤهلة المعلقة أو الجارية أو المكتملة التي لم تنجح ولا تملك مراجعة أحدث. لا يمكن إعادة إرسال طلب اكتمل بنجاح بهذا الإجراء.

تبدأ المراجعة الجديدة من أول خطوة. تبقى القرارات في النسخة السابقة وسجلات نتائجها، ولا تُتم مهام المراجعة الجديدة. راجع كل مشارك وخطوة قبل الإرسال.

استخدم **Show revision changes** عند ظهوره لفحص الملفات المضافة والمستبدلة والمحذوفة. تبقى الملفات القديمة سياقًا للمراجعة وليست ضمن الملفات الحالية المطلوب فحصها.

## حفظ النتيجة {#preserve-the-result}

تحفظ [سجلات النتائج](receipts.md) النتيجة والإجراءات وفق رؤية الخطوات. تُنشأ عند اكتمال الطلب أو إلغائه أو استبداله بمراجعة جديدة. راجع [الاحتفاظ والحذف](retention.md) قبل إزالة طلب أو الاعتماد على الوصول الطويل.

تمنع المراجعة الأحدث حذف الطلب الذي تشير إليه. ابدأ بجدولة حذف الأحدث، وانتظر التنظيف الخلفي قبل حذف السابقة. لا تزيل إزالة الطلب سجلات المشاركين.
