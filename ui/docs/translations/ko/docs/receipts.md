# 승인 완료 기록 및 문서 파일 확인 {#receipts-and-verification}

**완료 기록**은 요청이 완료되면 Click2Approve가 생성하는 기록입니다. 제공된 서명을 포함하여 요청 세부 사항, 결과 및 참가자의 기록된 작업을 보존합니다. 누가 행동했는지, 어떤 결과가 기록되었는지 확인하는 데 사용하세요.

인증 링크를 통해 완료 기록을 공유할 수 있습니다. 링크가 있는 사람은 기록을 검토하고 문서 사본이 완료 기록에 기록된 파일과 일치하는지 확인할 수 있습니다.

!!! info "완료 기록을 관리할 수 있는 사람은 누구인가요?"
    완료 기록이 발급된 사용자만 작업공간에서 완료 기록을 열거나 삭제하고 확인 링크를 관리할 수 있습니다. 이는 Personal와 조직 모두에 적용됩니다. 소유자와 관리자는 자신의 역할을 통해 다른 사람의 완료 기록을 열 수 없습니다.

요청이 완료되거나 취소되거나 새 버전으로 교체되면 요청자와 작업을 받은 모든 담당자가 완료 기록을 받습니다. 여러 작업이 있거나 요청자인 경우에도 각 사람은 작업 영역 및 요청 개정당 하나의 완료 기록을 받습니다. 완료 기록을 받기 위해 작업을 완료할 필요는 없습니다. 기록된 상태는 할당과 완료된 작업을 구별합니다. 작업을 생성하지 않은 단계는 담당자 완료 기록을 발행하지 않습니다.

## 완료 기록 열기 {#open-a-receipt}

요청을 보냈거나 작업을 완료한 작업 공간에서 **Receipts**를 연 다음 해당 요청에 대한 완료 기록을 선택하세요. **Receipt**카드 헤더에는 짧은 번호, 일치하는 요청 및 작업 카드 헤더가 포함되어 있습니다. 카드에는 전체 ID와 날짜가 표시되고 그 뒤에 기록된 세부 정보, 결과, 참가자, 작업 및 서명이 포함된**Request**및**Task**섹션이 표시됩니다.**Request**및**Task** 섹션 제목에는 워크스페이스 완료 기록과 공유 확인 페이지 모두에 짧은 번호가 포함되어 있습니다. 전체 요청 및 작업 ID는 가능한 경우 기록된 세부정보에 남아 있습니다.

수신 날짜는 초 없이 현지 날짜와 시간을 사용합니다. 빈 필드와 첫 번째 개정 번호는 숨겨집니다.

인쇄 시 요청 및 작업 섹션이 여러 페이지에 걸쳐 계속될 수 있습니다. 섹션 제목은 첫 번째 행에 유지되며, 개별 세부정보 행과 서명은 페이지에 들어갈 때 함께 유지됩니다.

완료 기록은 완료된 작업의 기록된 내용을 보존합니다. 참가자별 가시성은 완료 기록에 포함되는 단계를 제한할 수 있습니다. 완료 기록은 실시간 요청과 별개입니다.

## 확인 링크 생성 {#create-a-verification-link}

1. 관리할 수 있는 완료 기록을 엽니다.
2. **Share**를 선택하세요.
3. **New link**를 선택하고 **Expires**를 설정한 후 링크를 생성하세요.
4. 목록에서 생성된 링크를 선택하여 인증 URL을 연 후 복사하여 대상 수신자에게 공유하세요.

완료 기록 카드 내부의 QR 코드를 누르면 동일한 인증 링크가 열립니다. 카드 위의 Click2Approve 로고나 브랜드 이름을 선택하여 홈 페이지를 엽니다.

!!! warning "링크가 있는 사람은 누구나 완료 기록을 볼 수 있습니다."
    활성 확인 링크를 사용하면 워크스페이스 멤버십이 없어도 완료 기록이 열립니다. 공유하기 전에 검토하세요. 내용에는 이름, 결정, 서명이 포함될 수 있습니다.

## 파일 를 확인하세요 {#verify-a-file}

작업 공간이나 활성 확인 링크에서 완료 기록을 열고 **Verify file**를 선택하세요. 문서 사본을 선택하십시오. 브라우저는 파일 내용을 기반으로 값인 **SHA-256 hash**를 계산합니다. Click2Approve는 해당 값을 완료 기록에 기록된 해시와 비교하여 파일이 요청 파일 또는 참가자의 응답 첨부 파일과 일치하는지 여부를 보여줍니다. 이 검사는 브라우저에서 선택한 파일을 읽습니다. 해당 사본은 업로드되지 않습니다.

예를 들어 누군가 승인된 제안서와 완료 기록 링크를 보내면 링크를 열고 **Verify file**를 사용하여 제안서를 확인하세요. 내용이 변경된 파일은 파일 이름이 동일하더라도 기록된 해시와 일치하지 않습니다.

결과는 **Verify file**위에 표시됩니다.**File verified**는 일치하는 첨부 파일과 해당 요청 또는 작업을 식별합니다. **File does not match**는 기록된 파일에 동일한 해시가 없음을 의미합니다. 올바른 버전을 선택했는지 확인하고 다시 시도하세요.

확인에는 완료 기록에 보존된 파일 메타데이터와 해시가 사용됩니다. 원본 첨부 파일을 제거한 후에도 여전히 작동합니다. 완료 기록을 보관하더라도 저장된 첨부 파일은 보관되지 않습니다.

일치 여부는 파일 내용이 녹음된 파일과 일치함을 확인합니다. 문서의 주장을 평가하거나 서명자의 신원을 독립적으로 확인하지 않습니다.

## 공유 중지 {#stop-sharing}

**Share**에서 링크를 선택하고 **Remove**를 선택한 후 액세스가 더 이상 필요하지 않은지 확인하세요. 만료되거나 취소된 링크는 더 이상 완료 기록을 제공하지 않습니다. 다른 링크를 생성해도 기존 링크의 만료 기간은 연장되지 않습니다.

확인에 실패하면 완료 기록 소유자에게 현재 링크를 요청하세요. 공개 확인 링크는 조직의 요청, 작업 또는 디렉터리가 아닌 해당 완료 기록에 대한 액세스를 제공합니다.

## 완료 기록 보관 {#receipt-retention}

백그라운드 정리는 완료 기록 생성부터 측정된 완료 기록 작업 공간의 [보존 정책](retention.md)에 따라 완료 기록과 해당 확인 링크를 제거합니다.

| 계획 | 완료 기록 보관 |
| --- | --- |
| Personal Free | 5년 |
| Business Trial | 한 달 |
| 유료 플랜 | **Never delete**를 포함하여 구성된 **Requests and receipts** 기간 |

개인 담당자의 완료 기록은 요청 조직의 계획과 관계없이 Personal 작업공간의 정책을 따릅니다. 요금제를 변경하면 아직 삭제되지 않은 기존 완료 기록에 대한 정책이 변경됩니다. 원본 요청을 삭제해도 해당 요청의 완료 기록은 삭제되지 않습니다. 작업공간 제거 및 결제 관련 정리를 통해 완료 기록을 더 일찍 제거할 수 있습니다.

확인 링크는 완료 기록의 독립적인 백업이 아닙니다. 링크를 취소하면 완료 기록 삭제 없이 공유가 중지됩니다.

## 완료 기록 삭제 {#delete-your-receipt}

완료 기록에서 **Delete**를 선택한 다음 **Delete receipt**에서 확인하세요. 이렇게 하면 완료 기록과 모든 확인 링크가 영구적으로 제거됩니다. 다른 참가자에게 발행된 원본 요청이나 완료 기록은 삭제되지 않습니다. 소유자와 관리자는 자신에게 발행된 완료 기록만 삭제할 수 있습니다.

완료 기록을 보관하면서 공유를 중지하려면 대신 확인 링크를 취소하세요.
