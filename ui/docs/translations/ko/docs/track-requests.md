# 승인 상태 추적 및 요청 수정 {#track-and-revise-requests}

문서의 승인 상태를 확인하려면 요청을 소유한 작업 공간에서 **Requests**를 엽니다. 개인적으로 보내주신 작업물은 본인의 요청을 위한 워크스페이스 **Personal**를 이용해보세요. 조직을 대신하여 보낸 작업의 경우 해당 조직을 선택하세요.

사용 가능한 필터를 사용하여 요청을 찾은 다음 세부 정보를 열어 파일, 단계, 참가자 및 기록된 작업을 검토하세요. 귀하에게 할당된 작업의 경우 대신 **Tasks**를 엽니다. [작업 완료](complete-a-task.md)를 참조하세요.

## 진행 상황 및 결과 읽기 {#read-progress-and-outcomes}

워크플로 단계가 요청 요약 아래에 표시됩니다. 각 단계 제목에는 **Step 1 · Approve**와 같은 해당 번호와 작업이 표시됩니다. 제목을 확장하여 완료 규칙, 가시성, 요구 사항 및 원래 담당자를 확인하세요. 담당자 아이콘은 팀, 직원 및 이메일 주소를 식별합니다. 단계 세부정보를 축소해도 작업 카드는 계속 표시됩니다.

작업을 확장하여 팀 과제에서 나온 경우 **Assigned via**를 확인하세요. **Upcoming task**는 작업이 아직 시작되지 않은 사람을 표시합니다.

**From organization**는 작업에 표시되면 기록된 조직의 이름을 지정합니다. Personal는 조직이 아닌 작업 공간입니다.

각 요청 또는 작업 카드 헤더의 상태 칩은 카드가 접힌 경우를 포함하여 현재 상태를 표시합니다.

| 상태 | 의미 |
| --- | --- |
| Pending | 제출된 작업이 진행 대기 중입니다 |
| Started | 작업 흐름이 진행 중입니다 |
| Completed — Succeeded | 워크플로가 성공적으로 완료되었습니다 |
| Completed — Failed | 워크플로가 성공적이지 못한 결과로 완료되었습니다 |
| Canceled | 요청이 중지되었습니다 |
| Superseded | 최신 개정판이 이 요청을 대체했습니다 |

개별 작업 작업에는 서명됨 또는 거부됨과 같은 보다 구체적인 라벨이 있을 수 있습니다. 건너뛴 작업은 참가자가 결정을 내렸다는 의미는 아닙니다. 다른 결과로 이미 단계가 해결되었을 수도 있습니다. 자동으로 완료된 요청과 건너뛰거나 취소된 작업은 **Completed by** 필드 없이 상태와 완료 시간을 표시합니다.

## 요청 취소 {#cancel-a-request}

관리 권한이 있는 보류 중이거나 시작된 요청을 열고 **Cancel request**를 선택한 후 확인하세요. 취소하면 워크플로가 중지됩니다. 참가자에게 연락하기 전에 요청을 다시 열어 최종 상태를 확인하세요.

## 를 수정하고 다시 제출하세요 {#revise-and-resubmit}

Personal 또는 조직에서 적격 요청을 수정하세요.

예를 들어 검토자는 **Request changes**를 선택하고 제안서의 가격이 잘못되었다고 설명할 수 있습니다. **Resubmit**를 사용하여 제안서를 대체하고 새 검토를 시작하세요. [채팅](discussions.md)에 파일을 추가해도 요청의 현재 검토 파일은 대체되지 않습니다.

1. 적격 요청을 열고 **Resubmit**를 선택하세요.
2. 이전 개정판의 파일, 지침, 작업 흐름 단계를 검토하세요.
3. 새 개정판에 대한 파일, 지침, 단계를 업데이트하세요.
4. 참가자를 확인하고 **Submit**를 선택하세요.

다시 제출하면 새 개정판이 생성되고 이전 요청을 대체합니다. 이 작업은 성공하지 못했고 최신 개정이 없는 적격한 보류, 시작 또는 완료된 요청에 대해서만 제공됩니다. 성공적으로 완료된 요청은 이 작업을 통해 다시 제출할 수 없습니다.

새 개정판은 첫 번째 단계부터 워크플로를 시작합니다. 이전 결정은 이전 개정판과 그 완료 기록에 기록되어 있습니다. 새 개정판에서는 작업을 완료하지 않습니다. 다시 제출하기 전에 모든 단계와 참가자를 검토하세요.

**Show revision changes**(있는 경우)를 사용하여 추가, 교체 및 제거된 파일을 검사하세요. 교체되거나 삭제된 파일은 수정본의 컨텍스트로 유지되며 검토할 현재 파일의 일부가 아닙니다.

## 결과 보존 {#preserve-the-result}

[완료 기록](receipts.md) 단계 표시 여부에 따라 요청 결과와 각 참가자의 기록된 작업을 기록합니다. 요청이 완료되거나 취소되거나 새 개정으로 대체될 때 생성됩니다. 요청을 삭제하거나 장기간 액세스하기 전에 [보존 및 삭제](retention.md)를 검토하세요.

최신 버전에서는 참조하는 요청을 삭제할 수 없습니다. 먼저 최신 개정판 삭제를 예약한 다음, 이전 개정판을 제거하기 전에 백그라운드 정리를 기다립니다. 요청을 삭제해도 참가자의 완료 기록은 삭제되지 않습니다.
