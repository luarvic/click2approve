# 문서 승인 요청 생성 {#create-a-request}

승인을 위해 문서를 보내려면 **요청**을 생성하세요. 여기에는 검토할 파일, 지침, 각 참가자에게 수행할 작업을 알려주는 단계가 포함되어 있습니다. 승인, 검토 또는 전자 서명을 요청할 수 있습니다.

먼저 올바른 작업 공간을 선택하세요. 자신의 요청을 위한 작업 공간인 **Personal**를 사용하여 자신의 이름으로 작품을 보내세요. 대행하여 작품을 보낼 기관을 선택하세요. 작업 영역에 따라 요청을 소유한 사람과 사용할 수 있는 담당자 유형이 결정됩니다. **담당자**는 단계에 따라 조치를 취하도록 요청하는 개인 또는 팀입니다.

## 요청 작성 {#compose-the-request}

1. [앱을 열고](/app/) 작업 공간을 선택한 다음 기본 메뉴의 **Work**그룹 상단에서**New request**를 선택합니다.
2. 조직에서는 **Custom**또는**From template**를 선택합니다. 템플릿의 경우 해당 템플릿을 선택하고 요청 편집기로 이동하세요.
3. "업데이트된 공급업체 계약 승인"과 같은 구체적인 **Title**를 입력하세요.
4. 목적, 맥락, 예상 결과를 설명하는 **Description**를 추가하세요.
5. [참가자가 검토해야 할 파일](files.md)을 첨부하세요.
6. [워크플로 단계](workflow-steps.md)를 추가하고 구성합니다.

**Request details**카드는 제목,**Files to review** 및 설명을 그룹화합니다. 아래의 워크플로 단계를 구성하세요.

Personal 요청은 이메일 담당자를 사용합니다.

!!! info "조직 담당자"
    조직에서는 해당 조직의 직원과 팀에 단계를 할당할 수도 있습니다.

## 예: 다음에 대한 제안 보내기 승인 및 서명 {#example-send-a-proposal-for-approval-and-signature}

1. **Files to review** 아래에 제안서를 추가하세요.
2. **Action**가 **Approve**로 설정된 단계를 추가한 다음 리뷰어의 이메일 주소를 추가하세요.
3. **Add step**를 선택하고 **Action**를 **Sign**로 설정합니다. 클라이언트의 이메일 주소를 추가하고 **Require an electronic signature**를 활성화합니다.
4. 각 단계에 **Instructions**라고 적어서 두 사람 모두 확인해야 할 사항을 알 수 있도록 하세요.

클라이언트는 승인 단계가 성공한 후 작업을 받습니다. 여러 사람이 먼저 승인해야 하는 경우 승인 단계에 추가하고 **All assignees must complete**를 활성화하세요. 완료 규칙은 [워크플로 단계 구성](workflow-steps.md)을 참조하세요.

## 검토 및 제출 {#review-and-submit}

파일, 단계 순서, 작업, 지침, 참가자, 완료 규칙, 가시성 및 추가 요구 사항을 확인하세요. 서명이 필요한 경우 **Require an electronic signature**를 확인하세요. **Sign**작업만 선택하면 활성화되지 않습니다. 그런 다음**Submit**를 선택하고 페이지를 떠나기 전에 확인을 기다립니다.

필드가 강조표시되면 수정하고 다시 제출하세요. 계획 제한으로 인해 제출이 차단되는 경우 [사용법](usage.md)을 확인하거나 조직 소유자 또는 관리자에게 도움을 요청하세요.

조직 직원 이름이 불완전한 경우 기록에 어떻게 표시되는지 설명하는 경고가 표시됩니다. **Go back**를 선택하여 수정하거나 **Proceed anyway**를 선택하여 현재 이름으로 제출하세요. 조직 직원 세부정보는 개인 프로필과 별도로 관리됩니다.

맞춤형 새 조직 요청을 작성할 때 **Save template**는 제목, 설명 및 단계에서 비공개 템플릿을 생성합니다. 템플릿 유효성 검사 규칙을 적용하며 요청 제출을 대체하지 않습니다. 템플릿에서 시작된 요청 및 수정 요청은 이 작업을 제공하지 않습니다. [워크플로 템플릿](templates.md)을 참조하세요.

## 제출 후 {#after-submission}

**Requests**를 열고 요청을 선택하여 진행 상황을 따르세요. 참가자는 워크플로가 해당 단계에 도달하는 대로 행동합니다. 알림 전달은 각 수신자의 기본 설정을 따릅니다.

[요청 추적 및 수정](track-requests.md)을 사용하여 결과, 취소 및 수정 사항을 파악합니다. 작성 화면을 종료하거나 취소하면 확인 요청 없이 수정사항이 삭제됩니다. 요청 초안은 저장되지 않습니다.
