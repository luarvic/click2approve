# 승인 이메일 및 인앱 알림 {#notifications}

알림은 할당된 작업, 요청 결과, 토론, 완료 기록 및 청구 이벤트로 돌아가는 데 도움이 됩니다. 카테고리별로 게재 기본 설정을 별도로 지정하세요.

## 알림 검토 {#review-notifications}

앱의 알림 보기를 열어 인앱 이벤트를 검사하세요. 관련 리소스에 대한 알림을 따르고 조치를 취하기 전에 현재 상태를 확인하세요. 이전 알림은 이후 완료, 취소 또는 대체된 작업을 참조할 수 있습니다.

알림 및 이메일 제목에는 결과가 알려진 경우 **Step succeeded**또는**Step failed**및**Request succeeded**또는**Request failed**가 표시됩니다. 이메일 제목에 요청 제목을 추가합니다. 취소된 요청과 교체된 요청에는 별도의 이메일 제목이 있습니다. 다른 이벤트에서는 **New task**, **Task completed**(자동 완성용), **New message**및**New receipt**를 사용합니다.

이메일 링크는 관련 작업, 요청, 완료 기록 또는 계획 페이지를 대상으로 합니다. 메시지가 표시되면 원하는 계정으로 로그인하세요.

계정, 작업 흐름, 청구 이메일은 앱 바닥글을 홈, 앱, 문서, 연락처, 약관, 개인정보 보호 링크와 공유합니다. 보안 공지 및 배송 설명이 바닥글 위에 표시됩니다.

## 배송 기본 설정 지정 {#set-delivery-preferences}

1. **User profile → Notifications**를 엽니다.
2. 카테고리를 검토하세요: **Request notifications**, **Task notifications**, **Chat notifications**, **Receipt notifications**, **Retention deletion reminders**, **Billing recovery reminders**.
3. 지원되는 각 카테고리에 대해 **In-app**및**Email** 스위치를 설정하세요.
4. **Save**를 선택하세요.

저장된 기본 설정이 없는 카테고리가 활성화되기 시작합니다. 스위치를 변경하고 **Save**를 선택하여 기본 설정을 저장하세요.

**Billing recovery reminders**인앱 옵션이 비활성화되어 있습니다. 이메일 기본 설정은 다른 카테고리와 별도로 관리됩니다. 기본 설정은 귀하의 액세스 권한을 확장하거나 귀하를 토론 청중에 추가하지 않습니다.**Retention deletion reminders** 자동 보관 정리 전에 요청 및 완료 기록 소유자에게 경고합니다
해당 이메일은 보관 설정 및
[보관 및 삭제 가이드](retention.md)로 연결됩니다. 이 카테고리를 비활성화해도
보관 삭제가 비활성화되지는 않습니다.

## 메시지 누락 {#missing-messages}

이메일 주소, 스팸 폴더, 알림 기본 설정, 선택한 워크스페이스, 수신 자격 여부를 확인하세요. 이메일 전달에는 시간이 걸릴 수 있습니다.

지금 조치를 취해야 한다면 이메일을 기다리지 말고 작업 또는 요청을 직접 여세요. 전송 실패의 경우 자격 증명을 공유하지 않고 이벤트 시간 및 리소스 컨텍스트를 지원합니다.

## 이메일 토큰 {#email-tokens}

보존 알림을 포함한 워크플로 이메일은 수신자당 토큰을 소비하며 원래 작업 공간에 청구됩니다. 전송하기 전에 토큰을 확인하고 이메일 제공업체가 전송을 수락하면 요금이 청구됩니다. 알림을 대기열에 추가해도 토큰이 소비되지 않습니다. 비활성화된 이메일 전송에는 요금이 부과되지 않습니다. 보안, 계정 복구, 청구 이메일은 워크스페이스 토큰 요금 없이 포함됩니다. [사용량 및 토큰](usage.md)을 참조하세요.
