# 문서 검토, 승인 또는 서명 {#complete-a-task}

**작업**은 문서 승인 요청의 한 단계를 수행하도록 요청합니다. **Tasks**를 열어 귀하에게 할당된 문서를 검토, 승인 또는 서명하세요. 결정을 기록하기 전에 최신 문서와 지침을 읽어보세요.

## 작업 찾기 {#find-the-task}

1. [앱을 엽니다](/app/) 작업이 전송된 계정으로.
2. 작업 공간 선택기에서 귀하의 이메일 주소로 전송된 작업에 대해 **Personal**를 선택하세요. Personal는 귀하의 요청과 작업이 귀하에게 직접 전송되는 작업 공간입니다. 직원이나 팀 배정의 경우 조직을 선택하세요.
3. **Tasks**를 열고 작업을 대기 중인 작업을 선택하세요.
4. 제목, 요청자, 설명, 단계 지침 및 현재 파일을 읽어보세요.

팀 과제의 경우 **Assigned to**에는 작업을 받는 개별 직원이 직원 아이콘으로 표시됩니다. **Workflow**탭에서 단계 제목을 확장하여 원래 할당자와 설정을 검토합니다. 작업 카드는 제목 아래에 계속 표시됩니다. 팀이 생성한 작업을 확장하여 팀을 식별하는**Assigned via**를 확인하세요.

작업 및 요청 목록은 동일한 열과 너비를 사용합니다: **#**, **Title**, **Revision**, **Status**, **Requested by**및**Created**. 작은 화면에서는 제목 아래에 보조 세부정보가 표시됩니다. 작업을 열어 조직이 기록될 때 **From organization**를 확인하세요.

목록으로 돌아가려면 작업 제목 위에 있는 **Tasks** 탐색경로를 사용하세요.

조직에서 이메일로 처리되는 작업은 Personal에 도착합니다. 해당 조직의 작업 공간에 대한 액세스 권한을 부여하지는 않습니다. 조직 대리인은 승인된 작업을 수행할 수도 있습니다. [위임](delegations.md)을 참조하세요.

## 필수 정보 제공 {#provide-the-required-information}

작업 요약 아래에서 **Your response**를 사용하여 결정을 선택하고 필요할 경우 첨부 파일, 댓글, 서명을 제공하세요.

귀하에게 제공되는 작업을 사용하세요. 작업. 워크플로우에는 설명, 응답 첨부, 전자 서명 또는 이들의 조합이 필요할 수 있습니다. 제출하기 전에 모든 필수 필드를 작성하세요. 부정적인 결정에는 결과를 설명하는 의견이 필요합니다.

서명을 받으려면 **Legal name**를 확인하고 해당되는 경우 **Representation details**를 입력한 후 서명을 제공하세요. [저장된 프로필 서명](profile.md)으로 도면을 미리 채울 수 있습니다. 이 결정을 위해 검토하세요.

## 변경 승인, 거부 또는 요청 {#approve-reject-or-request-changes}

응답 선택은 단계의 **Action**에 따라 다릅니다. 다음은 몇 가지 일반적인 선택입니다:

| 단계 조치 | 긍정적인 반응 | 부정적인 반응 |
| --- | --- | --- |
| Approve | **Approve**|**Reject** |
| Review | **Review**|**Request changes** |
| Sign | **Sign**|**Decline** |

부정적인 응답에는 설명이 필요하며 실패한 결과로 요청이 중지됩니다. 예를 들어 검토 작업에서 **Request changes**를 선택하고 업데이트가 필요한 문서 부분을 설명합니다. 그런 다음 요청자는 [적격한 요청을 수정하고 다시 제출](track-requests.md#revise-and-resubmit)할 수 있습니다.

작업을 기록하기 전에 [채팅](discussions.md)을 사용하여 요청을 명확히 하세요. 채팅 메시지로는 작업이 완료되지 않습니다. 채팅으로 전송된 파일이 **Require an attachment**를 충족하지 않습니다. **Your response** 아래에 해당 파일을 추가하세요. [파일 및 첨부 파일](files.md)을 참조하세요.

## 결정 제출 {#submit-the-decision}

작업에서 부정적인 결과가 나올 때 부정적인 결과를 포함하여 결정에 맞는 조치를 선택하세요. 제출하기 전에 결정 사항과 확인 사항을 확인하세요. 성공 피드백을 기다리세요.

기록된 작업은 요청 기록의 일부가 됩니다. 성공적인 응답 후 단계는 완료 규칙에 따라 다른 담당자를 기다리거나 즉시 이동할 수 있습니다. 부정적인 응답은 실패한 결과로 워크플로를 종료합니다.

## 나중에 반환 {#return-later}

작업 페이지를 떠나면 확인 요청 없이 제출되지 않은 응답이 삭제됩니다. 결정을 기록하려면 작업을 완료하세요.

작업을 다시 열어 기록된 작업과 맥락을 검토하세요. 작업을 취소하거나, 건너뛰거나, 개정으로 대체하거나, 다른 적격 참가자가 완료한 경우 작업을 완료할 수 없게 될 수 있습니다. 오류가 발생한 후 작업을 다시 시도하기 전에 작업을 새로 고치세요.

작업 카드 헤더의 상태 칩에는 대기 중, 서명됨, 거부됨 등 현재 상태나 기록된 작업이 표시됩니다.
