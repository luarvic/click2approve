# 문서 승인 워크플로 단계 구성 {#configure-workflow-steps}

승인 워크플로는 문서 작업을 수행할 사람과 순서를 정의합니다. **담당자**는 단계에 할당된 개인 또는 팀입니다. 단계는 차례로 실행됩니다. 여러 담당자가 동일한 단계에서 작업을 수행할 수 있습니다.

**Add step**를 사용하여 다른 단계를 만들고, 화살표 컨트롤을 사용하여 순서를 변경하고, 제거 버튼을 사용하여 단계를 삭제하세요.

## 순차적 및 병렬 승인 {#sequential-and-parallel-approvals}

한 결정이 다른 단계보다 먼저 이루어져야 하는 경우 별도의 단계를 사용하세요. **순차승인**입니다. 예를 들어 검토자가 1단계에서 제안서를 승인한 후 고객이 2단계에서 서명합니다.

사람들이 동시에 검토할 수 있으면 같은 단계에 두십시오. 이는 해당 단계 내의 **병렬 승인**입니다. 단계 자체는 여전히 순서대로 실행됩니다.

| 당신은... | 이 방법으로 작업흐름을 구성하세요 |
| --- | --- |
| 한 명의 리뷰어와 다른 리뷰어 | 각 리뷰어에 대해 별도의 단계를 추가하세요 |
| 두 명의 검토자가 모두 승인해야 | 둘 다 하나의 단계에 추가하고 **All assignees must complete** 활성화 |
| 여러 사람 중 한 사람의 승인 | 이를 하나의 단계에 추가하고 **All assignees must complete**를 비활성화 상태로 둡니다 |
| 승인 후 서명 서명 | **Approve**단계를 추가한 다음**Require an electronic signature**가 활성화된 **Sign** 단계를 추가합니다 |

## 작업 및 참가자 선택 {#choose-an-action-and-participants}

각 단계에서 **Action**을 선택하고 명확한 **Instructions**를 작성하세요. 사용할 수 있는 작업은 Approve, Sign, Confirm, Acknowledge, Review, Verify, Accept, Complete입니다. 기록하려는 결정에 맞는 작업을 선택하세요.

제출하기 전에 이메일로 담당자를 추가하고 표시된 이름과 주소를 확인하세요.

!!! info "조직 담당자"
    조직에서는 **Employee**또는**Team**를 선택하여 할당하세요. 현재 조직 내에서 일합니다. 이러한 담당자 유형은 Personal에서 사용할 수 없습니다.

## 모든 담당자 또는 모든 담당자 필요 {#require-everyone-or-any-assignee}

모든 담당자의 성공적인 응답을 요구하려면 **All assignees must complete**를 활성화하세요. 이 옵션을 비활성화하면 하나의 성공적인 응답이 단계를 완료하고 다른 보류 중인 작업을 건너뜁니다. 스위치는 단계에 담당자가 여러 명이거나 팀 할당이 있을 때 나타납니다.

부정적인 결정은 **All assignees must complete**가 비활성화된 경우에도 실패한 결과로 요청을 중지합니다. 이 옵션은 다른 담당자가 거부를 무시하는 것을 허용하지 않습니다.

예를 들어 두 명의 검토자가 모두 조치를 취해야 하는 경우 한 단계를 사용한 다음 별도의 서명 단계를 수행합니다. 한 명의 참여자가 필요한 결정을 제공할 수 있는 경우 모든 담당자 옵션을 사용하세요.

## 추가 요구 사항 {#additional-requirements}

**Additional requirements**및**Visibility** 섹션은 요청을 생성 또는 수정하거나 템플릿을 편집하는 동안 각 단계에서 계속 표시됩니다. 저장하거나 제출하기 전에 설정을 검토하세요.

참가자가 충족해야 하는 요구 사항을 활성화합니다.

- **Require a comment** 설명을 수집합니다.
- **Require an electronic signature** 서명 세부 정보와 그려진 서명을 수집합니다.
- **Require an attachment** 응답 파일을 수집합니다.

작업 라벨과 전자 서명 요구 사항은 별도의 설정입니다. 그려진 서명이 필요할 때 서명 요구 사항을 활성화합니다. 참가자들이 무엇을 제공해야 하는지 알 수 있도록 선택한 작업과 함께 요구 사항을 검토하세요. [작업 완료](complete-a-task.md)를 참조하세요.

## 단계 가시성 {#step-visibility}

요청자와 단계의 직접 담당자는 이메일 담당자를 포함하여 항상 해당 단계를 볼 수 있습니다. **Visibility** 세부 사항과 응답 첨부 파일을 볼 수 있는 다른 사람을 제어합니다:

| 설정 | 추가 청중 |
| --- | --- |
| All participants | 요청에 대한 액세스 권한이 있는 참가자 |
| Assignees and organization participants | 조직 참가자; 조직의 작업 흐름에 사용 가능 |
| Assignees only | 추가 참가자 없음 |

이메일 할당은 이메일이 조직 직원에게 속한 경우에도 수신자의 Personal 작업 공간에 남아 있습니다. 할당된 단계는 워크플로에 계속 표시되고, 단계 채팅에 사용 가능하며, 수신자의 완료 기록에 포함됩니다.

이러한 설정은 워크스페이스 멤버십이나 관련 없는 요청에 대한 액세스 권한을 부여하지 않습니다. 다른 참가자에게 단계 세부정보가 필요하지 않은 경우 제한된 설정을 선택하세요.

## 수정 버전 {#revisions}

[요청을 다시 제출](track-requests.md)할 때 새 개정에 대한 단계를 검토하고 편집하세요. 워크플로는 첫 번째 단계부터 다시 시작됩니다. 이전 결정은 이전 개정판과 그 완료 기록에 계속 기록됩니다. 자주 사용하는 조직 워크플로의 경우 단계를 [템플릿](templates.md)으로 저장하세요.
