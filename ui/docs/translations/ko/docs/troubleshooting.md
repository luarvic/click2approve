# 문서 승인 문제 해결 {#troubleshooting}

승인 작업을 찾을 수 없거나, 요청을 제출하거나, 완료 기록 링크를 열 수 없다면, 먼저 계정과 선택한 워크스페이스를 확인하세요. 요청이나 작업을 열어 현재 상태를 확인하세요. 그런 다음 실패한 작업에 대한 오류 메시지를 읽어보세요.

## 요청 또는 작업 를 찾을 수 없습니다 {#i-cannot-find-a-request-or-task}

이메일 주소가 지정된 작업은 **Personal**에 나타납니다. 직원 및 팀 할당이 해당 조직에 나타납니다. 계정의 이메일, 직원 상태, 팀 멤버십, 위임 여부를 확인하세요. 작업이 취소, 건너뛰기, 완료, 대체 또는 삭제되었을 수도 있습니다.

이메일 링크는 조직에 액세스 권한을 부여하지 않습니다. [작업 공간 및 탐색](workspaces.md)을 참조하세요.

**Page not found**이 표시되면 페이지가 이동되었거나 해당 페이지에 액세스할 수 없는 것일 수 있습니다. 돌아가려면 **Home**을 선택한 다음 계정과 작업 공간을 확인하세요.

## 메뉴 항목 또는 작업이 누락되었습니다 {#a-menu-item-or-action-is-missing}

[기능 및 가용성](features.md)을 확인하세요. 직원, 팀, 위임 및 템플릿에는 조직 작업 영역이 필요합니다. 귀하의 역할, 계획 또는 청구 상태는 제어를 숨기거나 비활성화할 수 있습니다. 올바른 조직을 선택하고 소유자 또는 관리자에게 액세스 권한을 확인하도록 요청하세요.

## 업데이트 후 앱이 다시 로드됩니다. {#the-app-reloads-after-an-update}

앱이 새 릴리스를 감지하고 현재 페이지를 다시 열면 자동으로 다시 로드됩니다. 저장하지 않은 텍스트는 손실될 수 있습니다.

## 제출 또는 작업 완료 실패 {#submission-or-task-completion-fails}

강조 표시된 필드를 수정하고 필요한 모든 의견, 서명 및 첨부 파일을 제공하세요. 업로드가 완료될 때까지 기다립니다. 메시지에 허용량이 언급되어 있으면 [사용량](usage.md)을 확인하세요.

API 오류 후 다시 시도하기 전에 리소스를 새로 고치세요. 다른 참가자나 대리인이 이미 완료했을 수도 있습니다. 요청 또는 작업을 확인하여 원래 작업을 반복하기 전에 성공했는지 확인하세요.

## 요청을 수정할 수 없습니다 {#i-cannot-revise-a-request}

다시 제출은 최신 수정이 없고 성공적인 결과가 없는 적격 요청에 대해서만 사용할 수 있습니다. 새 개정으로 인해 워크플로가 다시 시작됩니다. 이전 결정은 이전 개정판에 그대로 유지됩니다. [요청 추적 및 수정](track-requests.md)을 참조하세요.

## 확인 링크가 작동하지 않습니다 {#a-verification-link-does-not-work}

링크가 만료되거나 취소되었거나 완료 기록이 삭제되었을 수 있습니다. 완료 기록 소유자에게 유효한 링크를 요청하세요. [완료 기록 및 검증](receipts.md).

## 로그인할 수 없거나 이메일 를 받을 수 없습니다 {#i-cannot-sign-in-or-receive-email}

이메일 확인이 필요한지 확인하고 필요한 경우 새로운 확인 또는 비밀번호 재설정 메시지를 요청하세요. 스팸과 계정 주소를 검사하세요. MFA의 경우 사용하지 않은 복구 코드를 사용해 보세요. 비밀번호의 경우 등록된 호환 기기 또는 비밀번호 로그인을 시도해 보세요.

[등록 및 로그인](sign-in.md), [MFA 및 비밀번호](security.md) 및 [알림](notifications.md)을 검토하세요.

## 결제를 위해 워크스페이스가 차단되었습니다 {#the-workspace-is-blocked-for-payment}

**Plans**를 열고 표시된 기한 전에 결제 복구 조치를 따르세요. 조직 소유자 또는 관리자는 조직 결제를 관리해야 합니다. [요금제 및 청구](plans-and-billing.md)를 참조하세요.

## 삭제가 차단됩니다 {#deletion-is-blocked}

종속성 메시지를 읽어보세요. 다른 레코드는 여전히 직원, 팀 또는 워크플로 엔터티를 참조할 수 있습니다. 관련 기록을 삭제하기 전에 [보존 및 삭제](retention.md)를 검토하세요.

## 도움을 받거나 버그를 신고하세요 {#get-help-or-report-a-bug}

앱의 **Report a bug**또는**Ask question**링크를 사용하세요. 재현 단계, 예상 결과, 실제 결과, 대략적인 시간 및 관련 작업 공간 유형을 포함합니다. API 오류로 인해**Details**가 발생하는 경우 진단 정보를 검토하고 지원 채널에 적합한 정보만 포함하세요.

비밀번호, API 토큰, 복구 코드, 확인 링크, 개인 문서는 공개 보고서에 포함되지 않도록 하세요. 계정, 이메일, 보안 또는 결제 문제가 있는 경우 지원팀에 문의하세요.
