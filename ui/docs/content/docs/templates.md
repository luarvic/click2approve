# Reuse document approval workflow templates {#workflow-templates}

Use workflow templates when you send documents through the same approval process often. A template saves request steps and participants inside an organization. You add the current documents when you create each request.

For example, save a proposal review step followed by a signing step. Reuse those steps for the next proposal, then check the reviewers, signer, and files before submitting.

Each template belongs to the person who creates it. Templates are private by default. Select **Shared** to let other active members of the same organization view and use a template. Only its creator can edit or delete it, including when another member is an Owner or Admin.

!!! info "Organization only"
    Select an organization to create and reuse workflow templates. Templates belong to that organization and are unavailable in Personal.

## Create a template

Open **Templates** in the organization and create a template with a descriptive name and reusable steps. Configure actions, instructions, assignees, completion rules, visibility, and additional requirements, then save.

Select **Shared** if other organization members should reuse it. Leave it unchecked to keep the template private. The template list shows **Shared** and **Owner** so you can identify available workflows and their creators.

Shared template names must be unique within the organization. Private template names must be unique among your own private templates in that organization. You can own both a shared **Budget** template and a private **Budget** template. Renaming a template or changing **Shared** must also satisfy these rules.

While composing a custom new organization request, **Save template** creates a private template from its title, description, and steps. It applies the same template validation rules and does not overwrite an existing template. If the title conflicts with one of your private template names, choose a different title before saving. Review what you save: a workflow template stores step configuration rather than a completed request or its recorded decisions.

## Start a request from a template

1. Choose **New request** in the same organization.
2. Select **From template**, choose one of your templates or a shared organization template, and continue.
3. Enter the request's title, description, and current documents.
4. Review every participant and step before choosing **Submit**.

Templates provide a starting configuration. Check that employees and teams are still appropriate for the new request. Do not assume a template supplies the files for a particular transaction.

The picker groups **Private templates** and **Shared templates** separately. Choose the name from the appropriate group when both contain a template with the same name.

The editor loads the template before you begin editing. Its name and description provide initial request text; change them for the current request before submitting.

## Maintain templates

Open **Templates** to update your recurring instructions and participant choices. Any active organization member can create and manage their own templates. Editing a template does not change requests that have already been submitted.

Templates shared by other members open in a read-only view. Ask the creator to update the template when its reusable steps need to change. Clearing **Shared** removes other members' access to the template; requests already created from it keep their copied workflow.

**Save template** is available only for custom new requests. To change an existing template, use **Templates**. Requests started from a template and request revisions do not offer **Save template**.

Remove unused templates with the available delete action. If deletion is blocked by a reference, follow the validation message rather than repeatedly retrying.
