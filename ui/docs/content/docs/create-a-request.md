# Create a document approval request {#create-a-request}

To send a document for approval, create a **request**. It contains the files to review, instructions, and steps that tell each participant what to do. You can ask for approval, review, or an electronic signature.

Choose the correct workspace first. Use **Personal**, your workspace for your own requests, to send work in your own name. Select an organization to send work on its behalf. Your workspace determines who owns the request and which assignee types you can use. An **assignee** is a person or team you ask to act on a step.

## Compose the request

1. [Open the app](/app/), select your workspace, and choose **New request** at the top of the **Work** group in the main menu.
2. In an organization, choose **Custom** or **From template**. For a template, select it and continue to the request editor.
3. Enter a specific **Title**, such as “Approve the updated supplier agreement.”
4. Add a **Description** explaining the purpose, context, and expected outcome.
5. Attach the [files participants should review](files.md).
6. Add and configure the [workflow steps](workflow-steps.md).

The **Request details** card groups the title, **Files to review**, and description. Configure the workflow steps below it.

Personal requests use email assignees.

!!! info "Organization assignees"
    In an organization, you can also assign steps to employees and teams from that organization.

## Example: send a proposal for approval and signature

1. Add the proposal under **Files to review**.
2. Add a step with **Action** set to **Approve**, then add the reviewer's email address.
3. Choose **Add step** and set its **Action** to **Sign**. Add the client's email address and enable **Require an electronic signature**.
4. Write **Instructions** for each step so both people know what to check.

The client receives a task after the approval step succeeds. If several people need to approve first, add them to the approval step and enable **All assignees must complete**. See [Configure workflow steps](workflow-steps.md) for the completion rules.

## Review and submit

Check the files, step order, action, instructions, participants, completion rule, visibility, and additional requirements. If you need a drawn signature, check **Require an electronic signature**; choosing the **Sign** action alone does not enable it. Then choose **Submit** and wait for confirmation before leaving the page.

If fields are highlighted, correct them and submit again. If a plan limit blocks submission, inspect [Usage](usage.md) or ask an organization Owner or Admin for help.

If your organization employee name is incomplete, a warning explains how it will appear on the record. Choose **Go back** to correct it, or **Proceed anyway** to submit with the current name. Organization employee details are managed separately from your personal profile.

In an organization, **Save template** saves reusable step configuration. It does not replace submitting the request. See [Workflow templates](templates.md).

## After submission

Open **Requests** and select the request to follow its progress. Participants act as the workflow reaches their steps. Notification delivery follows each recipient's preferences.

Use [Track and revise requests](track-requests.md) to understand outcomes, cancellation, and revisions. Leaving or canceling the compose screen discards edits without asking for confirmation. Request drafts are not saved.
